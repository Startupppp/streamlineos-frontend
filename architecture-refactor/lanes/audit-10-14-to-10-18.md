## New Findings

### NF-1 (P2) — useMailMessages fires without useCan gate
**File:** `frontend/hooks/api/mail.ts:33–55`
**Finding:** `useMailMessages` is an `useInfiniteQuery` with no `enabled: useCan("mail:inbox:view")` guard. The backend endpoint `GET /mail/messages` requires `@RequirePermission("mail:inbox:view")`. CLAUDE.md §2 (frontend): "Gate every query: `enabled: useCan('<the endpoint's exact @RequirePermission key>')`."

The `/mail` route is declared universal in `frontend/lib/rbac/route-access/universal-routes.ts` line 32, and `mail:inbox:view` is in role defaults, so a 403 in practice is low probability. The concern is architectural: if a future role change or test user lacks the key, the hook fires a 403-destined request on every mount, burning Neon CPU and producing silent failures. `frontend/app/(authenticated)/mail/layout.tsx` calls `await enforceRouteAccess("/mail")` server-side, but client-side hooks must still carry the gate per the CLAUDE.md rule.

**Fix:** Add `enabled: useCan("mail:inbox:view")` to `useMailMessages`. This does not change the universal-route posture; it aligns the hook with the contract rule.

### NF-2 (P2) — notifications/page.tsx renders unbounded list without windowing
**File:** `frontend/app/(authenticated)/notifications/page.tsx` line 244
**Finding:** The notification list renders accumulated `useInfiniteQuery` pages via `items.map((n: Notification, idx) => ...)` inside `AnimatePresence`. As the user clicks "Load older notifications," each page appends to the DOM without any `react-window` virtualization. CLAUDE.md §3 (frontend): "An `items.map(...)` with no pagination, `slice` or windowing is a hang-risk bug." An inbox with hundreds of notification pages can accumulate thousands of DOM nodes.

The mail list (`frontend/features/mail/mail-virtual-list.tsx`) uses `react-window` `List` correctly — this is the model to follow. `react-window` v2 `List` with `AnimatePresence` at the window boundary (not per-item) is the correct fix.

**Fix:** Replace the bare `items.map()` with a `react-window` `List` following the `MailVirtualList` pattern. Keep `AnimatePresence` at the list boundary.

### NF-3 (P2) — mail.service.ts checkpoint save is fire-and-forget
**File:** `backend/src/modules/mail/mail.service.ts` (checkpoint save call)
**Finding:** `void this.checkpoints.savePosition(...)` in the sync path is fire-and-forget. The 10.17 [x] checked bullet (NF-3 is distinct from it) covers `NotificationDispatchService.emit()` callers only. The mail sync checkpoint is a separate instance of the same pattern.

If the checkpoint write fails silently, the next sync re-processes already-seen messages, causing duplicate display and potentially duplicate send/receive side effects. Per backend CLAUDE.md §4: "Never swallow a deferred failure, or the next outage is invisible too."

**Fix:** Await `this.checkpoints.savePosition(...)` or, if it must be non-blocking, wrap it in `registerAfterCommit` with a logged error on failure — never a bare `void`.
