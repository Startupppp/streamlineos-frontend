## CROSS-LANE P0 — 20 tables had no grants to the app role

Found by the billing session on a `POST /billing/checkout` 500; confirmed here because it
was breaking `/chat` outright. On a journal-built database, 20 tables across
`public/app/build/build_events` had **no privileges at all** for `streamline_app`.

**It breaks reads, not just writes.** `chat-message-timeline.service.ts` reads
`chat_message_reactions`, so loading any channel raised `42501` and `/chat` rendered an
error boundary — which made the CH7 matrix refuse at preflight. The first diagnosis here
was **wrong**: it was recorded as probable harness fixture drift, plausible because this
session changed the chat client contracts and a wrong contract renders as an empty state.

Three traps that make it expensive: `42501` reads as an RLS denial while RLS is *disabled*
on these tables; the sequence grant is separately load-bearing so a table-only fix fails
*identically*; and `GRANT ON ALL TABLES` is point-in-time, so tables created by later
migrations are uncovered — which is exactly how it recurred.

Fixed in `1111`, which pairs the 20-table backfill with `ALTER DEFAULT PRIVILEGES` bound to
`current_user`, verified by creating a table in a rolled-back transaction and confirming the
app role reached it unaided. Severity beyond this lane: on the billing path the provider
order is created **before** the local insert, so a failure between them leaves the customer
charged, the payment recorded, and **no subscription term granted** — recoverable by hand,
silent until noticed. That ordering defect is owned by billing and is NOT fixed.

## What the browser gates found that jsdom could not

**1. A visible `isError` branch can be unreachable dead code.** Inbox and chat both had
`ErrorState` + "Try again" that could never render: the query inherited
`throwOnError: readErrorReachesBoundary`, so an error with no cached data threw past the
component into the route boundary, which is terminal — that is the "never recovered" half.
Worst case: `useChatUnreadTotal` sits in the app sidebar **above** the `(authenticated)`
boundary, so one 500 on a decorative badge took **every authenticated route** to the root
error page. Fixed with `INLINE_READ_ERROR`. ⚠ **Not universal** — `useCalendarEvents` keeps
`throwOnError` legitimately, because `/calendar/error.tsx` resets the query error-reset
boundary and its retry measurably re-issues the request. Check the boundary recovers before
treating `throwOnError` as the bug.

**2. One shared overlay produced false findings in all three lanes.**
`components/workspace-onboarding/success-checklist.tsx` started uncollapsed below `md` and
owned the pixels of controls beneath it. On inbox it faked "Enter/Space/click reach
different handlers"; on chat it cost two cells; on calendar it produced **five** bogus
findings at once by navigating to `/settings/users`, so the matrix photographed the Settings
error boundary and truthfully reported the calendar list was absent. Measured, not inferred:
`elementFromPoint(281,132)` returned `span :: Invite your first teammate`.

**3. Contrast failures were the token pair, not opacity modifiers.**
`--muted-foreground` #64748b on `--muted` #f1f5f9 = **4.34:1**, and calendar's `EVENT_COLORS`
rendered white text at **2.28-3.68:1**. The repo's `text-muted-foreground/NN` remedy does not
apply to a failing pair.

**4. A `.next` that moves under a live server makes a matrix photograph the harness.** A
peer's failed `next build` cleared `.next`; the run produced 28 "defects" that were
`InvariantError: client reference manifest … does not exist`. That run was **voided, not
reported**. A green `next build` does not prove every route emitted its manifest —
smoke-request each route for 200 first.

## Shared defects found by these lanes, and their fixes

All six were approved and implemented after the lanes closed:

| Defect | Fix |
| --- | --- |
| `--muted-foreground` on `--muted` 4.34:1 | light token → `#556377`; **5.58:1** on `--muted`, 5.84 on `--background`, 6.11 on `--card`, and **5.10 worst tinted theme** (rose, previously 3.97). Dark measured and needs none (6.63:1) but is now asserted. |
| Onboarding checklist pointer theft | defaults to collapsed below `md`, viewport-derived and SSR-safe |
| `scroll-area` keyboard access | viewport `tabIndex={0}` by default + `viewportTabIndex` opt-out (122 call sites checked) |
| Chat nav gap 640-767px | `sm:hidden` → `md:hidden`, both reserved insets `max-sm:` → `max-md:`, plus an invariant test that the two surfaces cannot both be hidden at any width |
| Permanently-mounted modal | `role`/`aria-modal`/`aria-label` now exist only while open |
| rbc orphan ARIA roles | normalised to `presentation` on `.rbc-allday-cell` for **timed views only** |

**Two premises of mine were wrong and are corrected here.** There is no `role="dialog"` in
`workspace-onboarding/**` at all — the 640px dialog a probe read was the mobile FAB. And the
month grid measures **clean**; normalising it would orphan its `role="cell"` date cells and
*create* a violation, which a bite test proves. If the browser counted month-view states
among calendar's 10 FAILs, that has a cause jsdom does not reproduce and is still open.

**Two tests were pinning defects rather than catching them** — a contrast test asserting
`toBeLessThan(4.5)` (so fixing the token would have turned a green test red) and a FAB test
asserting the dialog is always in the DOM. Both strengthened.
