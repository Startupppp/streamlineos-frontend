## 1. c25-03 — four navigation gates name a permission no route enforces

`pnpm check:navigation-permissions` (new, `backend/src/scripts/check-navigation-permissions.mjs`)
reproduces this on demand and names every offender. **Re-run it rather than trusting this table.**

The defect in one sentence: the sidebar shows a destination to whoever holds key A, and the endpoints
behind it enforce key B. Holding A shows a link that 403s; holding B works but the link is hidden.
Neither is visible in review because both keys exist in both catalogs.

| Nav gate | Where | The route actually enforces | Destinations affected |
|---|---|---|---|
| `accounting:view` | `frontend/components/layout/sidebar/sidebar-nav-groups-finance.ts:9` (group) and every route from `:16` to `:259` | `accounting:read` and its per-surface siblings (`accounting:receivables:read`, `accounting:journal:read`, `accounting:periods:read`, `accounting:settings:read`, …) | ~40 |
| `accounting:report` | `sidebar-nav-groups-finance.ts:273, 279, 285, 291, 297, 303` | `accounting:reports:read` | 6 |
| `crm:deals:approve` | `sidebar-nav-groups-crm.ts:107` → `/crm/deals/approvals` | `crm:deals:read` (`backend/src/modules/deals/deals-approvals.controller.ts:53`) | 1 |
| `hr:goals:view` | `sidebar-nav-routes-hr-employee-experience.ts:72` → `/hr/goals` | `hr:performance:view` (`backend/src/modules/hr/performance/performance.controller.ts:65`) | 1 |

**Which side is wrong is not symmetric.** `accounting:view` and `accounting:report` live in
`permissions/shared.ts:17,30` and are enforced by **zero** routes, while `accounting:read` and 23
sibling keys in `permissions/accounting.ts` are enforced by the real controllers. The nav is the
stale side; move each destination to the key its own endpoint checks. That is per-destination work —
`/accounting/banking` and `/accounting/taxes` do not read the same key — so it is a real frontend
task, not a find-and-replace, which is why S3 did not guess it.

`hr:goals:view` and `crm:deals:approve` are granted by role templates
(`role-templates.constants.ts:115, 210`) but enforced nowhere, so they currently confer nothing.

**Not blocking anything of S3's** except wiring `check:navigation-permissions` into CI, which stays
unwired while it exits 1.

## 2. c25-01 — the 50 routes still carrying no exposure declaration

Supersedes `lane-requests/lane-2.md` §1, which listed 107. S3 applied 57. **Re-run
`pnpm check:route-classification` rather than trusting this table** — and note it under-reported by
five until 2026-08-27, because it could not read a decorator prettier had wrapped.

Adding `@Universal()` to a handler under a class that carries only `@UseGuards(JwtAuthGuard)` is
**metadata with no runtime effect** while `REQUIRE_ROUTE_CLASSIFICATION` is off — check that first,
because if the class carries a class-level `PermissionGuard` instead, §2's rule applies: move the
guard onto the gated handlers rather than deleting a key.

| Owner | File | Handlers | S3's reading |
|---|---|---|---|
| **S5** | `modules/notifications/notifications.controller.ts` | 17 | `@Universal()` — own inbox; root §8 names notifications platform core. **This is the group that keeps the flag off:** enforcing today 403s every member's notifications |
| **S5** | `modules/notifications/notification-preferences.controller.ts` | 10 | `@Universal()` — the caller's own preferences |
| **S5** | `modules/notifications/broadcasts.controller.ts` | `listInbox`, `dismiss` | `@Universal()` — own inbox |
| **S4** | `modules/chat/chat-entity-actions.controller.ts` | 3 | `@Universal()` — chat is §8 platform core; confirm each derives its subject from `@CurrentUser()` |
| **S4** | `modules/chat/chat-actions.controller.ts` | `createTaskFromMessage` | needs the owning lane's call: it **creates a Build ticket** from a message, so the authorization that matters may be the Build one, not the chat one |
| **S4** | `modules/search/search.controller.ts` | `globalSearch` | `@Universal()` **only after** confirming results are filtered by the asker's access in the SQL predicate (`backend/CLAUDE.md` §4). If they are not, that is a disclosure bug and the declaration is the smaller half of it |
| **S1/S2** | `modules/billing/core/billing.controller.ts` | `getEntitlements` | `@Universal()` — own org's entitlements; root §8 has the frontend read this through `useEntitlements` |
| **S1/S2** | `modules/billing/core/billing.controller.ts` | `getPlans`, `getMarketplace` | plan catalog. `@Public()` if genuinely pre-auth, otherwise `@Universal()`. **Not `@RequirePermission`:** `assertPermissionsGrantable` refuses the whole `billing:` namespace on every path, so no billing key can ever be held by a non-owner |
| **HR** | `modules/hr/onboarding/core/onboarding.controller.ts` | 9 | `@Universal()` — a new joiner completing their own onboarding holds no permissions yet, so a key would deny every legitimate caller |
| **HR** | `modules/hr/config/hr-document-types.controller.ts` | `list`, `getOne` | `@RequirePermission` — HR configuration, not self-service |
| **HR** | `modules/hr/hub/hr-hub.controller.ts` | `getSnapshot` | `@RequirePermission` — HR administration |
| **HR** | `modules/hr/enterprise-ops/emergency/emergency.controller.ts` | `respond` | needs HR's call — an emergency response path may be deliberately reachable without a key |

`REQUIRE_ROUTE_CLASSIFICATION=true` must not be set, and `check:route-classification` must not be
wired into CI, until this reaches zero.
