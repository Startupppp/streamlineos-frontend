## 1. `streamline_app` cannot authenticate — one root cause blocks three separate items

`APP_DATABASE_URL` in `backend/.env` fails `28P01 password authentication failed for user
'streamline_app'`. `DATABASE_URL` (`neondb_owner`) connects normally, so the branch is alive and the
credential has drifted.

This single fact blocks, verified this session:

- **c13-06** — "sorting composes with the tenant-led indexes". Measuring as the owner proves nothing;
  `BYPASSRLS` hides exactly the effect being tested.
- **c13-04** — the `accounting-receivables-list` read budget cannot be measured, so its 50,000-block
  ceiling stays a placeholder.
- **The entire e2e suite** — see item 2.

**Fix it in the Neon console, not with `ALTER ROLE`.** Neon's control plane restores the previous
password when the branch suspends, so an `ALTER ROLE` repair lasts until the next idle timeout.

## 2. Every e2e suite requires a reachable database, which the harness says it does not

`DrizzleModule.assertRlsIsEnforced` (`backend/src/db/drizzle.module.ts:81`) runs inside
`onApplicationBootstrap` and queries Postgres, so `createE2eApp` cannot boot without a live
connection. `test/helpers/e2e-app.ts` opens by stating the opposite — "none of them needs a
database" — and stubs membership, entitlements and access precisely so a guard-chain suite can run
dry. That design is currently defeated one layer below it.

Measured: `projects.controller.e2e-spec.ts` is unmodified and reports **65 failed, 0 passed** in this
checkout, all from `app.init()`. Against an unreachable host it fails identically (`ECONNREFUSED`),
so this is not the credential drift alone — a reachable database is required either way.

Suggested: let `assertRlsIsEnforced` degrade to a logged warning when the connection is unavailable,
or skip it when `NODE_ENV === "test"`. Not applied here — `db/drizzle.module.ts` is shared.

## 6. `notifications/broadcasts.service.ts` still cursors inline

It builds `lt(id, cursor)` by hand rather than calling `buildIdCursorPage`
(`backend/src/common/pagination/cursor.ts:112`), which is the trim-the-sentinel step chat's three
surfaces had each copied — and copied wrongly, taking the cursor from the discarded sentinel row and
permanently skipping it. The same shape is the same risk. Outside S4's territory; this is the last
named surface in c13-05's first criterion that is fixable by one lane.

## 7. The Build ticket list stays page-numbered, deliberately

`useProjectBoardTickets` (`frontend/hooks/api/build/ticket-queries.ts:37`) is an infinite query that
walks `GET /build/:projectId/tickets` by page number and auto-loads up to 500 rows, so it is exactly
the scrolled-and-concurrently-written shape c13-05 exists for. Converting it means a cursor mode on
the endpoint, a keyset predicate per sortable column, and a frontend change — and it would still
leave the criterion unticked, because `notifications` is in another lane either way.

Weighed against that: no database is reachable to measure the new plan against, four sessions share
this checkout, and the board is the product's busiest screen. S4 did not convert it. It is recorded
here as the one piece of c13-05's first criterion that is in a single lane's territory and still open.
