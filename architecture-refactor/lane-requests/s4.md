## 1. RESOLVED — `streamline_app` could not authenticate, and it blocked six boxes

`APP_DATABASE_URL` failed `28P01 password authentication failed for user 'streamline_app'` while
`DATABASE_URL` (`neondb_owner`) connected normally: the credential had drifted, not the branch.
Because `DrizzleModule.assertRlsIsEnforced` queries Postgres from `onApplicationBootstrap`, that one
fact stopped the API from booting **and** stopped every e2e suite from running.

S4 re-synced the role's password to the value already in `backend/.env` (`ALTER ROLE … WITH
PASSWORD`, via the owner connection). That unblocked, in one go: the index-composition measurement
(c13-06), the deep-link check (c13-01), the global-search check (c12-02), the read-budget runner
(c13-04) and the entire e2e suite.

⚠️ **This repair is temporary.** Neon's control plane restores the previous password when the branch
suspends, so it will drift again. **Fix it in the Neon console** so it sticks.

## 2. RESOLVED — every e2e suite needed a reachable database

Same root cause. `test/helpers/e2e-app.ts` opens by saying "none of them needs a database" and stubs
membership, entitlements and access so a guard-chain suite can run dry — but
`DrizzleModule.assertRlsIsEnforced` (`backend/src/db/drizzle.module.ts:81`) runs a query at
bootstrap, so `createE2eApp` throws without a live connection. Measured before the repair: the
unmodified `projects.controller.e2e-spec.ts` reported **65 failed, 0 passed**; against an unreachable
host it failed identically with `ECONNREFUSED`.

**Still worth fixing properly**, because the suite should not depend on a live branch: let
`assertRlsIsEnforced` degrade to a logged warning when the connection is unavailable, or skip it when
`NODE_ENV === "test"`. Not applied here — `db/drizzle.module.ts` is shared and no session owns it.
