## 2. `verifyPaymentSchema` does not carry `billingCycle`

**Owner:** whoever owns `backend/src/modules/billing/core/dto/billing.schemas.ts`.

`createOrder` prices an annual purchase at 12 × monthly less the annual discount, but
`verifyAndActivate` has no cycle, so it records `subscription_payments.amount` at the **monthly**
price and sets `currentPeriodEnd` one month out. An annual customer is recorded as monthly.

```ts
export const verifyPaymentSchema = z.object({
  // …
  billingCycle: billingCycleSchema.optional(),
});
```

Then `verifyAndActivate` should use `planBaseAmountPaise(plan, cycle, ANNUAL_DISCOUNT_PCT)` for the
recorded amount and add 12 months to `currentPeriodEnd` for `annual`. `coupon_redemptions.amount`
is left null for the same reason — the discount cannot be computed without the cycle.

## 3. `provider_webhook_events` uniqueness is global, not tenant-scoped

**Owner:** whoever owns `backend/migrations/0490_provider_webhook_events.sql` and the journal.

`uq_provider_webhook_events_provider_event` is `(provider, provider_event_id)`. Unique indexes are
enforced regardless of RLS, so an organisation posting a validly-signed webhook against **its own**
endpoint can pre-insert another organisation's `provider_event_id` and have that organisation's
genuine event swallowed. backend/CLAUDE.md §3 requires tenant-scoped uniqueness to be composite.

0490 is unapplied, so the cheapest fix is to edit it in place:

```sql
CREATE UNIQUE INDEX IF NOT EXISTS "uq_provider_webhook_events_provider_event"
  ON "provider_webhook_events" ("org_id", "provider", "provider_event_id");
```

S1 handles the current state rather than working around it: `ProviderEventLedger.claim` returns
`FOREIGN` when the insert conflicts but no row is visible to the tenant, and the endpoint answers
409 with an error log instead of reporting success.
