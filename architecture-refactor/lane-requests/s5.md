## Note on `notifications` being partitioned

`0582` makes `notifications` a RANGE-partitioned table on `created_at`. Two consequences for anyone
touching it:

- Its primary key is now `(id, created_at)` and `uniq_notifications_org_id` is
  `(org_id, id, created_at)`. A bare `id` is no longer globally unique.
- `notification_deliveries` and `notification_audit_logs` each carry `notification_created_at` and
  reference the pair. **MATCH SIMPLE skips a composite foreign key when any column is NULL**, so
  any new insert path that sets `notification_id` must set `notification_created_at` too, or the
  constraint silently does not apply. The dispatch service does this at both writers.

`chat_messages` and `notification_outbox` are **not** partitioned, deliberately — see c21-04.
