## 3. Plan change must call `ProrationLedgerService.recordPlanChange` — blocks c26-03

`billing.service.ts` is S1's this session. Its plan-change / subscription-update path is the only
caller that can produce a proration line.

```ts
await this.prorationLedger.recordPlanChange({
  orgId,
  subscriptionId,
  idempotencyKey: `sub:${subscriptionId}:${newPriceVersionId}:${effectiveFrom.toISOString()}`,
  oldPriceVersionId,
  newPriceVersionId,
  oldQuantity,
  newQuantity,
  periodStart: currentPeriodStart,
  periodEnd: currentPeriodEnd,
  effectiveFrom,
});
```

Do not pass an amount or a line type. The service computes the amount from the two price versions
and derives `UPGRADE` / `DOWNGRADE` / `QUANTITY_CHANGE` from the money, so a caller cannot label a
downgrade an upgrade. When the provider reports its own figure, call
`reconcileProviderAmount(orgId, idempotencyKey, providerAmountMinor, providerRef)` — it stores the
provider number beside the computed one and returns the variance rather than overwriting anything.
