## Item 3.1 — Author membership on version tables (DONE)

**Gap:** `kbPageVersions` and `kbArticleVersions` tracked the editor by `authorId` (userId string) only. The migration program moving from userId to membershipId as the canonical actor (migrations 0661/0662/0670) left version tables untouched.

**Fix:**

- `db/schema/kb/page-collab.ts`: added `authorMembershipId: integer("author_membership_id")` to `kbPageVersions`
- `db/schema/kb/versions.ts`: added `authorMembershipId: integer("author_membership_id")` to `kbArticleVersions`
- `migrations/0679_kb_versions_author_membership.sql`: `ALTER TABLE kb_page_versions ADD COLUMN IF NOT EXISTS author_membership_id integer; ALTER TABLE kb_article_versions ADD COLUMN IF NOT EXISTS author_membership_id integer;`
- `migrations/meta/_journal.json`: entry added at idx 395
- `kb-page-edit.util.ts` `snapshotIfNeeded`: added `authorMembershipId: number | null = null` parameter (backward compatible default); writes to insert
- `kb-pages.service.ts`: passes `this.membershipId(user)` to `snapshotIfNeeded`
- `kb-page-versions.service.ts`: imports `actingMembershipId`; passes to both `snapshotIfNeeded` calls; adds `authorMembershipId` to `VERSION_COLUMNS`
- `kb-articles.service.ts`: imports `actingMembershipId`; `snapshot` method accepts `membershipId: number | null = null`; all 4 callers pass `actingMembershipId(user.principal)`

## Item 3.2 — Resumable ingestion (PARTIAL, NOT FULLY CLOSED)

**What is present:**
- Async via outbox — `OutboxWriter.emit` → `KbIngestionConsumer` processes `kb.content.index` events ✓
- Content-hash deduplication — `isContentUnchanged` hashes the **source text** (not rejoined chunks) with `sha256`; unchanged content is skipped ✓
- ACL-only update path — when content hash matches but ACL fields changed, only the ACL columns are updated without re-embedding ✓
- Observable — `Logger` warns on concurrency limit, errors on extract failure ✓
- Per-org concurrency cap — `KB_MAX_CONCURRENT_PER_ORG = 20` ✓

**What is absent:**
- Chunk-level resumption: a crash mid-document re-runs the entire document from scratch (atomic delete+insert per document is the boundary, not per chunk)
- Malware scan: attachments are extracted without any virus/malware check before indexing
- Structured progress tracking: no persistent checkpoint table

These require design decisions (per-chunk checkpoint table, scanning service integration) before implementation.

## Item 4.1/4.2 — Two-KB consolidation (DECIDED: KEEP BOTH)

**Decision:** Keep both systems as live products. The evidence is in the code itself.

`KbArticleConversionModule` (`kb-article-conversion.module.ts`, line 7):
> "Permanent operator tool, not a transition: the help centre is a live product with full article CRUD, so this backlog never drains and this module never becomes deletable."

**Distinct semantics that prevent merger:**

| Dimension | Help-centre (articles) | Wiki (pages) |
|---|---|---|
| Schema | `kbArticles` in `db/schema/support/kb.ts` | `kbPages` in `db/schema/kb/pages.ts` |
| Audience | External customers / public | Internal org members |
| Visibility model | `public` / `internal` | `private` / `org` / `public` + project-scope |
| Structure | Category + slug-URL | Tree (parentPageId) + space |
| Content type | Plain text (Markdown) | Rich Plate JSON with 10 content types |
| Workflow | Author → publish | Draft → in_review → published → archived + review cycles |
| Versioning | `kbArticleVersions` | `kbPageVersions` with window-based snapshots |
| ACL | Space membership + restriction list | Space membership + project scope + creator scope |

Both share `kbArticleChunks` for vector storage (distinguished by `articleId` vs `pageId` nullability). The conversion scripts (`pnpm convert:kb-articles`) are permanent operator tools for orgs that want to migrate their help-centre content to wiki, not a platform-level deprecation path.

No code change needed. Decision recorded here.
