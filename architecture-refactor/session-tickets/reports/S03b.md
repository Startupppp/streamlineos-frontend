## 2. Cursor pagination (items 6.1 / 6.2 / 6.3)

`listBatches` in `payout-batches.service.ts` uses `buildCursorPage` + `decodeCursor` from `common/pagination/cursor.ts`. The schema (`batchesQuerySchema`) validates `cursor?: string` and `limit` with `.max(100)`, hard-capping at `BATCH_LIST_CAP = 100`. `buildCursorPage` returns `nextCursor: null` (not `undefined`) when exhausted — the sentinel defect is not present. ## 4. expense_export_jobs schema drift (item 7)

The prior report noted this as "schema drift" (column name mismatch). Investigation shows it was actually an RLS defect: the policy on `expense_export_jobs` used `app.current_org_id` (wrong GUC key) while the app sets `app.organization_id`, so every tenant query returned zero rows.

Migration `0677_rls_fix_guc_key.sql` drops and recreates the policy using `current_org_id()` (the function that reads the correct GUC). The migration is present in `backend/migrations/` and journaled in `_journal.json` (`tag: "0677_rls_fix_guc_key"`).

No schema drift to repair — the column name in migration `0659` and the live column are aligned. The RLS fix is the correct closure.

**Item 7: CLOSED (RLS defect fixed by migration 0677, journaled).**
