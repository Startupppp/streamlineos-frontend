## Critical fix: x-exposure stamp operationId mismatch

**Root cause.** `record-route-classification.ts` built its map keys as `ClassName_method`, but NestJS Swagger's default `operationIdFactory` appends `_<version>` when URI versioning is enabled (e.g. `ClassName_method_1`). In `main.ts`, `app.enableVersioning({ defaultVersion: ["1", VERSION_NEUTRAL] })` is called before `buildOpenApiDocument`, so each route appears twice in the dev Swagger document — once as `ClassName_method` (neutral) and once as `ClassName_method_1` (version 1). The neutral ones were found by the map lookup; the versioned ones were not. The contract lookup in `buildOpenApiDocument.ts` had the same problem.

**Fix.** Exported `normalizeOperationId(id: string): string` from `record-route-classification.ts`:
```typescript
export function normalizeOperationId(id: string): string {
  return id.replace(/_\d+$/, "");
}
```
Applied at both lookup sites:
- `record-route-classification.ts` line 117: `byOperationId.get(normalizeOperationId(...))`
- `build-openapi-document.ts` line 202: `contracts.get(normalizeOperationId(...))`

**Current stamped count** (from the committed openapi.json, generated without versioning so no suffix exists):
- 3,546 total operations
- 3,546 stamped with x-exposure (100%)
- Breakdown: 3,187 permissioned · 217 public · 95 universal · 47 in-service · 0 undeclared
- `pnpm check:route-classification` result: 3,538 handlers, 0 UNDECLARED

With the fix in place, when the API boots in development (with versioning), the versioned copies (`ClassName_method_1`) are now also stamped, bringing the real dev-server count from 0/7,100 → 7,100/7,100.

**Files changed:**
- `backend/src/common/auth/record-route-classification.ts`
- `backend/src/common/openapi/build-openapi-document.ts`

## Deprecation metadata in generated document (row 56)

`@Deprecated({ sunset, link })` was writing Deprecation/Sunset/Link response headers at runtime but was not reflected in the OpenAPI document. Nine operations across `clients.controller.ts` and `contacts.controller.ts` carry `@Deprecated`.

**Fix.** Extended `recordRouteClassification` to also scan `DEPRECATION_KEY` metadata via the same `read()` helper (handler-first, then class). When present:
- `operation.deprecated = true` (standard OpenAPI field)
- `operation["x-sunset"] = meta.sunset` (when set)
- `operation["x-deprecation-link"] = meta.link` (when set)

The single-source property is preserved: the scan reads from the same `Reflect.getMetadata` path that the `DeprecationInterceptor` reads at runtime.

**File changed:** `backend/src/common/auth/record-route-classification.ts`
