## 1. Fixes Applied

### 1a. `backend/jest-e2e.json`

Three changes:

### 1b. `backend/test/e2e-suite-exit-guard.cjs` — NEW

Jest's `--forceExit` causes OOM-killed workers to emit exit code 0. The processor checks `testExecError` and `status === "failed" && testResults.length === 0` and sets `process.exitCode = 1` when either is present. Verified: ran `schema-catalog-parity` (which has a real failure); the guard correctly emitted exit code 1.

### 1c. `backend/test/helpers/db-describe.ts` — NEW

Ten specs gate on `RBAC_E2E_DATABASE_URL` with `describe.skip` — silently passing in CI. Created `describeWithDb`:

```ts
function loudSkip(name: string, fn: () => void): void {
  process.stderr.write(`\nSKIPPED (no DB): "${name}" — set RBAC_E2E_DATABASE_URL to run this suite\n`);
  describe.skip(name, fn);
}
export const describeWithDb: SuiteFactory = RBAC_E2E_DATABASE_URL ? describe : loudSkip;
```

### 1d. Weak assertion fixes

**`agent-tokens.controller.e2e-spec.ts`** — test "cross-tenant: revoke returns 404 not 403" asserted `not.toBe(403)`, which a 500 also satisfies. Fixed:
- Mock changed from `Object.assign(new Error("Not found"), { status: 404 })` to `new NotFoundException("Agent token not found")`. (`AllExceptionsFilter` passes `HttpException` status through; plain `Error.status` is ignored → 500.)
- Assertion changed to `expect(res.status).toBe(404)`.

**`e-sign-signing-flow.e2e-spec.ts` (lines 235, 247, 265)** — three "blocks signing" assertions used `rejects.toThrow()` (satisfied by any error). Changed to `rejects.toThrow(ForbiddenException)`. Verified: `sign-public.service.ts` `assertActive()` throws `ForbiddenException` for non-active sessions.

**`module-access.controller.e2e-spec.ts` (line 135)** — `jest.clearAllMocks()` in `beforeEach` does not drain `mockResolvedValueOnce` queues. A failure before the HTTP call would bleed the Once value into the next test. Changed to `jest.resetAllMocks()`. The `beforeEach` re-establishes all default mock values after reset, so this is safe.

### 1e. Stale ts-jest cache — cleared

`%LOCALAPPDATA%\Temp\jest\jest-transform-cache-*` contained stale compiled output for ~70 controllers. These files had old compiled JavaScript that referenced `ZodValidationPipe` (from before the migration to `@Validate({body:schema})`), but without the corresponding import. When any spec loading `AppModule` ran, Node.js evaluated those stale compiled modules and threw `ReferenceError: ZodValidationPipe is not defined` at module load time, killing the entire spec suite before any test ran.

Both cache directories deleted. The `--no-cache` flag also added to test commands to prevent re-accumulation during migration.

### AppModule targeted run: agent-tokens (completed)

Command: `node --max-old-space-size=6144 ./node_modules/jest/bin/jest.js --config ./jest-e2e.json --runInBand --forceExit --no-cache --testPathPattern="agent-tokens.controller"`

| Metric | Value |
|---|---|
| Tests passed | 3 |
| Tests failed | 6 |
| Wall time | 972 s (~16 min) |

**All 6 failures are 402 (Module Disabled).** The `agent-tokens` routes are blocked by the global `ModuleGuard` for all tokens including those using `ALL_MODULES`. This is a **pre-existing spec defect** that was hidden by the stale cache (the suite never reached test execution before). The three passing tests are the 401-on-unauthenticated cases that the module gate does not affect.

**What our assertion change surfaced:** The old assertion `expect(res.status).not.toBe(403)` passed on 402 (any non-403 satisfies it). The new `expect(res.status).toBe(404)` fails correctly — the response is 402, not 404. The mock is correct (`NotFoundException` → `AllExceptionsFilter` → 404), but the module gate blocks before the service call is reached. The 402 pre-existed; the weak assertion hid it.

**Root cause of 402:** The module key for `agent-tokens` routes is not present in the token produced by `ALL_MODULES`. The `settings:api-tokens:*` permission namespace resolves to a module that `moduleIds()` either does not include or includes under a different key than `ModuleGuard` expects. Fixing this is out of scope for lane E2E2 — it requires auditing `moduleIds()` against the module vocabulary.
