# S05d — Cursor Migration: Finance Tax Payments & Reminder Policies

## Task

Migrate `listTaxPayments`, `listReminderPolicies`, and `listReminderLog` to the shared cursor contract (cap 100, explicit `null` nextCursor on exhaustion). Remove legacy offset branches. Migrate every caller.

## Root Cause of Deferral

Both services had a dual-path: cursor branch when `cursor` or `limit` was set, offset branch otherwise. The offset branch was kept because the frontend still sent `page`/`pageSize`. S09 is now closed — the block was stale.

## Bug Fixed

The old cursor path returned `nextCursor: result.nextCursor === undefined ? null : String(result.nextCursor)`. Since `buildIdCursorPage` returns `number | null` (never `undefined`), `String(null)` evaluated to the string `"null"` when the list was exhausted — collapsing the exhausted state with the in-progress state in JSON.

## Bounded Lists — Judgment

The following lists are judged bounded (not migrated from offset):

- `tax-codes`: finite enumeration of GST/VAT code variants, typically <20 per org.
- `asset-categories`: static category list, typically <20 per org.
- `reconciliation-rules`: set of matching rules, typically <10 per org.
- `approval-policies`: set of spend approval chains, typically <10 per org.
- `exchange-rates`: reference data, bounded by currency count.

All other growing lists (credit notes, recurring invoices, AR payments, vendor payments, transfers, bank imports, payment runs, etc.) remain on offset pagination — migrating them was not in scope for this deferred item which specifically named tax payments and reminder policies.
