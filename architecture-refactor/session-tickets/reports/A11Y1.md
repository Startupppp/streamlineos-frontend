## Defects Found and Fixed

### 1. Dialog/Sheet missing accessible title — 4 defects fixed

`SheetContent` (backed by Radix Dialog) requires a `SheetTitle` (= `DialogTitle`) so screen readers receive an accessible dialog name via `aria-labelledby`. Without it, Radix emits a warning and ATs announce the dialog as unlabelled.

**Root cause:** Components were rendering the visible title inside a plain `<div>` or `TruncatedText` inside `SheetHeader`, bypassing the Radix title slot.

**Files fixed:**
- `features/calendar/external-event-detail-sheet.tsx` — replaced `TruncatedText` with `SheetTitle` (also removes unused import)
- `features/calendar/hr-event-detail-sheet.tsx` — same replacement
- `features/chat/message-panel-side-panels.tsx` — two mobile-only sheets wrap panels that own their own visual headers; added `sr-only SheetTitle` ("Saved messages" / "Shared files") inside each `SheetContent`
- `app/(authenticated)/chat/page.tsx` — mobile `ChannelInfoPanel` sheet: added `sr-only SheetTitle` ("Channel info")

**Not fixed:** `app/(authenticated)/build/[projectId]/chat/page.tsx` — same pattern but in the live build lane.

### 2. Form label / control association — 12 labels fixed

`<label>` elements placed as siblings to their controls (not wrapping them) with no `htmlFor`/`id` pairing. Screen readers cannot associate the label text with the control.

**Files fixed:**
- `features/candidates/candidate-sheets.tsx` — `ScheduleInterviewSheet`: Type select, Date & Time, Duration, Meeting Link; `ApplyToJobSheet`: Job Posting select. Added `htmlFor` on labels and matching `id` on `SelectTrigger`/`Input`.
- `features/chat/device-selector.tsx` — Microphone `<label>` + `<select>`, Speaker `<label>` + `<select>`. Added `htmlFor`/`id` pairs.
- `app/(authenticated)/crm/settings/assignment-rules/page.tsx` — Lead Score `<Input>` and City `<Input>` in the preview panel. Added `htmlFor`/`id` pairs. (Lead Source / Lead Priority use custom `CrmOptionSelect` which wraps Radix Select — not fixed here as that requires changing the component API.)

**Pattern still present** (not fixed in this pass — excluded modules or complex Select wrappers): `features/hr/**`, `features/candidates/**` detail tabs, `app/(authenticated)/hr/**`. The correct long-term fix is to migrate all ad-hoc form sections to `EntityFormSheet` + `FormField`/`FormItem`/`FormLabel`/`FormControl` which auto-wire `htmlFor`/`id`.

### 3. Focus visibility — 2 defects fixed

`focus:outline-none` without a visible replacement on interactive controls that are not inside a `focus-within`-labelled container.

**CLEAN (container provides indicator):**
- `message-input.tsx` — container: `focus-within:border-status-info-rule focus-within:shadow-lg`
- `thread-panel.tsx` — container: `focus-within:border-status-info-rule`
- `chat-search-dialog.tsx` — container: `focus-within:border-primary/50`
- `forward-message-dialog.tsx:169` — input: `focus:border-primary/40`

**Fixed:**
- `features/chat/chat-bubble.tsx:226` — inline-edit textarea container had `border-primary/40` always (non-responsive to focus). Added `focus-within:ring-2 focus-within:ring-ring/50` to the container div. The container uses `overflow-hidden` so ring is applied on the element itself using `box-shadow`, which is not clipped.
- `features/chat/forward-message-dialog.tsx:126` — search input container (`border-border/50`, no focus indicator). Added `focus-within:border-primary/50 transition-colors`.

**Not fixed:** `features/chat/huddle-chat-panel.tsx` — video-call overlay with white text on dark background; `focus-within:ring-white/40` would be the correct fix but this is a specialized floating UI.

---

### 4. Table column scope — shared primitive fixed

`TableHead` (`<th>`) lacked `scope="col"` by default. Screen readers use this attribute to understand the header-cell relationship in data tables, especially for users navigating with table reading mode.

**File fixed:** `components/ui/table.tsx` — added `scope="col"` as default prop on `TableHead`. Callers can override with `scope="row"` if needed.

**Impact:** All `DataTable` and raw `<Table>` usage across the codebase inherits `scope="col"` automatically.
