## Defects fixed in this session

### Production code fixes

**1. `storage.module.ts` — AvScannerModule DI export**
- Root: `StorageModule.exports` included `AvScanner` directly (a provider from the
  imported `AvScannerModule`). NestJS v11 rejects exporting a provider that isn't
  owned by the current module; must re-export the containing module.
- Fix: `exports: [StorageService, AvScannerModule]` (was `AvScanner`).
- Affected spec: `crm-automations-products.e2e-spec.ts` — 29 tests now passing.

**2. `record-layouts.controller.ts` — layoutKeySchema not enforced**
- Root: the params schema used `z.string().min(1)` instead of `layoutKeySchema`
  (which validates against the registered `RECORD_LAYOUT_KEYS` catalog). Invalid
  keys like `"crm:invoice"` or SQL injection strings returned 200.
- Fix: import and use `layoutKeySchema` in the params object.
- Affected spec: 4 tests in `record-layouts.controller.e2e-spec.ts` flipped to green.

**3. `inv-stock-adjustments.service.ts` — FK violation returns 500**
- Root: inserting adjustment lines with non-existent `productVariantId` or
  `locationId` throws a postgres-js SQLSTATE 23503 that propagated as 500.
- Fix: wrap the `db.transaction` in try/catch; map `sqlstateOf(err) === "23503"` to
  `BadRequestException`.
- Affected spec: 2 tests in `adjustments.e2e-spec.ts` flipped to green (7/7 total).

**4. `kb-page-visibility.ts` — undefined membershipId produces SQL 42601**
- Root: `actingMembershipId(principal)` can return `undefined` at runtime when the
  test harness provides a principal without `membershipId`. The `=== null` guard
  passes for `undefined`, so Drizzle generates a broken query:
  `"created_by_membership_id" = ` with no bind parameter → SQLSTATE 42601.
- Fix: change to `== null` (catches both `null` and `undefined`).
- Impact: eliminates unhandled-exception log entries from `GET /kb/pages/tree` in
  every e2e suite that exercises the KB page tree with a stub principal.

### Test harness fixes

**5. `test/helpers/e2e-app.ts` — membershipStub.resolve missing membershipId**
- Root: `MembershipStateService.resolve()` returns `MembershipState` which includes
  `membershipId: number | null`. The stub returned only `{ active, isOwner, role }`.
  The guard checks `state.membershipId === null` — with `undefined` that check is
  `false`, so `humanSessionPrincipal(undefined, false)` is constructed, and
  `actingMembershipId` returns `undefined` instead of `null`.
- Fix: `resolve` stub now returns `membershipId: 1`.
- Prevented: SQL 42601 on the KB page tree endpoint in all specs where the handler
  is reached.

**6. `test/public-contact.e2e-spec.ts` — RecruitmentService deleted, missing deps**
- Root: `PublicController` was refactored — `RecruitmentService` renamed to
  `PublicCareersService`, and `PublicOffersService`, `PublicReferrersService`,
  `WaitlistService` added as new constructor dependencies. The spec still imported
  the deleted file.
- Additional root: `ContactService` injects `APP_CONFIG` and `TurnstileService` but
  the spec provided neither, so `createTestingModule` failed. The spec also lacked
  `ZodValidationInterceptor`, so the strict-schema test was returning 201 instead
  of 400 for unknown fields.
- Fix: update imports; provide `APP_CONFIG`, `TurnstileService` (env-reading mock),
  the three new services, and install `ZodValidationInterceptor` globally.
- Result: 4/4 tests passing.

**7. `finance.controller.e2e-spec.ts` — routes pointing to non-existent handlers**
- Root: four test routes pointed to base GET paths where no handler exists
  (`/accounting/customer-statements`, `/accounting/expenses`,
  `/accounting/insights`, `/accounting/taxes/adjustments`). Also two permission
  keys `"accounting:tax:read"` should be `"accounting:taxes:read"`.
- Fix: update routes to existing sub-routes; fix permission key strings.
- Result: 57/57 tests passing.

**8. `chat-entity-actions.controller.e2e-spec.ts` — @Idempotent requires header**
- Root: `POST /chat/entity-actions/submit` carries `@Idempotent("chat.action.submit")`
  which returns 400 without the `Idempotency-Key` header. Four submit tests omitted it.
- Fix: add `.set("Idempotency-Key", "test-key-...")` to all four tests.
- Result: 10/10 tests passing.

**9. `surveys.controller.e2e-spec.ts` — wrong participants route**
- Root: test used `POST /surveys/:surveyId/participants` which doesn't exist; correct
  route is `/surveys/:surveyId/participants/invite`.
- Fix: update route string.
- Result: 25/25 tests passing.

## Contamination and environment findings

**Stale Jest transform cache causes intermittent DI failures**
Running concurrent shard instances (e.g., 3 shard-3 processes simultaneously) can
result in Jest workers using a stale compiled artifact for recently modified files.
Symptom: `Nest can't resolve dependencies of OrgSetupService … OrgSetupResolverService`
even though the file exists and is listed in `OrgModule.providers`. Clears with
`pnpm test:e2e:ci --clearCache`. This is environmental, not a code bug.

**OOM kills from parallel shard execution**
Running more than one shard concurrently on this machine (8 GB heap each) causes
workers to be SIGTERM'd for exceeding available memory. Affected specs:
`risks.controller.e2e-spec.ts`, `adjustments.e2e-spec.ts` in the contaminated
shard-3 run. Both pass in isolation.

**`OrgSetupResolverService` refactor is uncommitted work**
`org-setup-resolver.service.ts` is an untracked file; `org-setup.service.ts` and
`org.module.ts` are locally modified. This is in-progress work from a parallel agent
and is not part of E2E4's scope.
