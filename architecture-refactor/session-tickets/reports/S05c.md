## What remains unaddressed in projection audit

- `assets.service.ts` list uses `select({ asset: accFixedAssets, categoryName: ... })` — the `asset: accFixedAssets` pattern returns all asset columns as a nested object. Changing this to flat columns would break `frontend/features/accounting/assets/asset-table.tsx` which accesses `row.asset.id`, `row.asset.name`, etc. (outside this session's territory: `app/(authenticated)/accounting/assets/page.tsx`). No sensitive data in `accFixedAssets`. Left as-is pending a coordinated frontend+backend change.
- Internal single-row business logic lookups (e.g. `findOrThrow` in assets, workflow methods in bills) that legitimately need all columns from the fetched row to perform their computation.
