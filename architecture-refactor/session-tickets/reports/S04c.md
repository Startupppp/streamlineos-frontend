## Bug fixed

**File:** `backend/src/modules/build/core/projects-tickets-read.service.ts` line 146

**Root cause:** The direct-member path in `checkProjectAccess` queried `projectMembers` by `projectId + userId` without joining `organizationMembers`. A user whose org membership was SUSPENDED or LEFT still had a row in `projectMembers`, so the check returned `hasAccess: true` for them. The `resolveUserPermissions` path already checked `status = ACTIVE`; only this direct path was unguarded.

**Fix:** Added an `innerJoin(organizationMembers, and(eq(organizationMembers.userId, userId), eq(organizationMembers.orgId, orgId), eq(organizationMembers.status, "ACTIVE")))` to the query. A suspended org member whose join condition fails now returns no rows, so `hasAccess: false`.

**Imports added:** `organizationMembers` from `../../../db/schema`.
