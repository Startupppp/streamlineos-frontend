## Findings

### CRITICAL: Cross-org isolation bug in `tax-compliance.service.ts`

**Root cause:** `checkTaxDue()` accepted an optional `orgId`. When called from `cron-finance.service.ts` via `forEachOrg` (which sets the ambient GUC to org-X), the method called `getAllActiveOrgIds()` and iterated all orgs. For any org-Y ≠ org-X, `computeNetLiability(org-Y)` ran `WHERE invoices.orgId = org-Y` under an ambient GUC of `app.current_org_id() = org-X`. RLS policy `eq(org-Y) AND GUC=org-X` → 0 rows. Only the ambient org got a correct notification; all others were silently skipped.

**Fix:** Added `import { getTenantContext } from "../../../common/tenant"` and changed line 55:
```
// Before
const orgIds = orgId ? [orgId] : await this.getAllActiveOrgIds();
// After
const effectiveOrgId = orgId ?? getTenantContext()?.orgId;
const orgIds = effectiveOrgId ? [effectiveOrgId] : await this.getAllActiveOrgIds();
```

When called from `forEachOrg`, `getTenantContext()?.orgId` returns the current org from ALS, limiting the sweep to that org — matching what the ambient RLS GUC allows.

### 8 `void` → `await` cache invalidation fixes

`CacheService.invalidate()` catches its own errors internally, so `void` vs `await` is purely a timing issue. Callers using `void` returned responses BEFORE the cache was invalidated, so the next request could get stale data. Changed to `await` in:
- `payment-runs.service.ts` (2 sites: `approveRun`, `cancelRun`)
- `recurring-bills.service.ts` (3 sites: `createTemplate`, `updateTemplate`, `deleteTemplate`)
- `vendor-credits.service.ts` (3 sites: `createVendorCredit`, `postVendorCredit`, `applyVendorCredit`)

### 6 bare `.catch(() => [])` swallows in insights service

`computeAnomalies()` in `insights.service.ts` ran 6 finders in `Promise.all`, each with `.catch(() => [])`. Finder failures were silently dropped. Changed each to log via `logSideEffectFailure(finderName, { orgId })` before returning the fallback empty array.
