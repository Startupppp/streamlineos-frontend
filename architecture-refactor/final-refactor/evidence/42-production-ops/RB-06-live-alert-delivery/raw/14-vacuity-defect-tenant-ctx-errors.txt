# DEFECT (found while running RB-06, not fixed — outside this agent's write scope)
# alert-tenant-ctx-errors.mjs reports CLEAR (exit 0) on an EMPTY or BROKEN log stream.
# run 2026-09-03T16:27:13Z  backend SHA=138709f35befcd558c86ab04f65edf8344f6a545

Three of the five log-backed detectors guard against an empty stream and exit 2:
  alert-p95.mjs            -> exit 2, 'No lines with message="SPAN" ... the span exporter is unwired'
  alert-seam-latency.mjs   -> exit 2, 'No seam span lines found'
  alert-pool-saturation.mjs-> exit 2, 'No db.pool.wait span lines ... pool telemetry is unwired'
alert-tenant-ctx-errors.mjs has no such guard. Its threshold is 0 occurrences, so zero input
lines is indistinguishable from zero 42501 errors and it exits 0.

This matters because tenant-ctx-errors is registered severity=critical in alert-dispatch.mjs
REGISTRY, and because the runbook's own stated failure mode is 'a webhook that 200s into a dead
channel'. The equivalent here is a predicate that reads a dead pipe and reports healthy.

===== control 1: empty stream =====
$ node src/scripts/alert-tenant-ctx-errors.mjs < /dev/null
{"fired":false,"count":0,"threshold":{"maxOccurrences":0,"windowHours":1},"destination":"CONFIGURE_ME — wire exit-code 1 to your oncall system","matches":[]}
EXIT=0

===== control 2: a broken stream (wrong journalctl unit -> plain-text, non-JSON lines) =====
$ printf '%s
' '-- No entries --' 'Failed to add match: Invalid argument' | node src/scripts/alert-tenant-ctx-errors.mjs
{"fired":false,"count":0,"threshold":{"maxOccurrences":0,"windowHours":1},"destination":"CONFIGURE_ME — wire exit-code 1 to your oncall system","matches":[]}
EXIT=0

===== positive control: the SAME script on a stream that DOES contain a 42501 line =====
$ printf <one real-shaped ERROR_REPORT line with sqlstate 42501> | node src/scripts/alert-tenant-ctx-errors.mjs
{"fired":true,"count":1,"threshold":{"maxOccurrences":0,"windowHours":1},"destination":"CONFIGURE_ME — wire exit-code 1 to your oncall system","matches":[{"timestamp":null,"correlationId":"rb06-probe","orgId":"drill-4373b133","route":"/notifications","message":null}]}
EXIT=1

So the predicate is CORRECT (it fires on a 42501 line) but VACUOUS-SAFE-FAILING:
it cannot distinguish 'no errors' from 'no input'. p95/seam-latency/pool-saturation can.
Suggested fix (NOT applied here): count lines read and exit 2 when zero lines arrived,
matching the guard alert-p95.mjs already has at src/scripts/alert-p95.mjs:194-197.
