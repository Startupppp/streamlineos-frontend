Both closed, delete-then-insert in one transaction with ACL columns populated from the page row. **RESIDUE:** page revisions are **not immutable**. `kb-page-edit.util.ts:44-51` hard-deletes the oldest row once a page passes `MAX_VERSIONS = 100`, so it is a rolling window, not a ledger; the 101st edit destroys revision 1. - [x] Concentrate page/article visibility at the data seam for content, comments, reviews, attachments, search and retrieval; prove revocation and ACL predicates before keyword/vector/model context. — the AR-06 work (Help Centre comments, Wiki comment re-authorization, freshness-review scope) was already landed and re-verified against current source. Retrieval was traced end to end for `/kb/ask`: HTTP → `KbSearchService.retrieveTopArticles` → four candidate queries → prompt assembly. **ACL is in the SQL, not the prompt**, on every branch: keyword article candidates carry `inArray(spaceId, accessibleSpaceIds)` + `status='published'` + a correlated `articleRestrictionFilter()`; keyword page candidates carry `pageVisibleTo()` on live `kbPages` columns; vector candidates `INNER JOIN` on `chunks.aclRevision = page/article.aclRevision`, which is a SQL `=`, so a stale chunk (revision mismatch, or NULL on either side) is **excluded** — the re-index window fails closed rather than open. Read/search parity holds because the final fetch re-applies the same live `pageVisibleTo`/restriction predicates the direct read uses. - [x] Verify bounded cursor CRUD/search/review/export contracts and resumable idempotent ingestion, chunking, embedding, deletion and reindex workers with leases, cancellation and DLQ. — contracts: `searchSchema` caps `q` at 200 chars and 50/page, `askSchema` caps the question at 1,000, chat history and research briefs cap at 100, import caps at 100 items × 50,000 chars. **Three unbounded or unvalidated reads found and fixed:** `KbArticleReindexService.reindexAll` loaded *every* published article for an org with no limit and no cursor (now keyset-paged at 100, mirroring the proven `reindexAllPages`); `getBacklinks` materialised every inbound link row and expanded it into an `ANY(ARRAY[...])` (now capped at 200); and both review list endpoints read raw `@Query()` with **no `@Validate`**, so `afterDueAt`/`afterId` reached the keyset code unvalidated (strict Zod schemas added in `dto/`, per §6 never inline in the controller). Workers: leases are Redis `NX` with a 300s TTL and a Lua release, retries are bounded by `shouldDeadLetter(retryCount)` into a DLQ, cancellation is a real `AbortController` threaded into `adapter.handle()`, and article/page chunking is resumable through `KbIngestionCheckpointService` with content-hash skip. **Embedding was the weak point:** source and attachment indexing fired `Promise.all(chunks.map(embedQuery))` — one HTTP call per chunk, all at once, non-resumably, so a 500-chunk document opened 500 simultaneous provider requests and lost all progress on the first rate-limit. `EmbeddingsService.embedBatch` already existed and had **zero callers**; all three sites now batch through it at 64, sequentially, with order asserted. A cross-tenant existence oracle was also closed: `listConversations` accepted any conversation id in the system as a cursor (`eq(id, cursor)` with no tenant predicate).
- [ ] Route all AI calls through the backend gateway with deterministic authorization, atomic token-credit reserve/settle, bounded context/tools/concurrency and abort/deadline/circuit-breaker behavior. — **four of five clauses closed; two named residues keep it open.** PROVEN: the reserve is genuinely atomic — `ai-credits-reservation.service.ts` takes `SELECT … FOR UPDATE` on the wallet row inside a savepoint before the balance check, so two concurrent requests serialize and cannot both pass; settle locks both rows and refunds the under-run in integer milli-credits. Authorization is deterministic and finishes before retrieval (`ToolAccessService.denyReason` per tool, `@RequirePermission` on every route, rate-limit tiers verified present for all six AI keys). **Three defects found and fixed.** (a) **Output tokens were unbounded at the gateway** — a caller omitting `maxTokens` inherited whatever the provider defaulted to, while `AI_FEATURE_COSTS` are reserve *ceilings*, so a long completion silently overran its reservation; the gateway now bounds every path at 4,096 and clamps a caller asking for more. (b) **Client aborts never reached the provider on the non-streaming path** — `AiGatewayRunnerHelper` accepted no signal and `LlmService.attempt()` had none, so a disconnected client left the call running and, worse, left the retry loop free to walk the whole model chain (up to 9 attempts × 30s) for a request nobody was waiting for; `signal` is now threaded runner → `attempt()` → `client.invoke(messages, { signal })`, with `throwIfAborted()` before each attempt and an abort short-circuit that stops retrying. (c) **The chat circuit breaker could never open.** `recordCbFailure()` was called only in the `catch` around `buildStream()`, but `streamText()` returns synchronously and provider faults surface asynchronously on the stream — so `cb.failures` stayed 0 forever and `isCbOpen()` was permanently false. `onError` is now wired, with client aborts excluded so a user cancelling does not trip the breaker on everyone else. **RESIDUE:** (i) **embeddings do not route through the gateway at all** — `EmbeddingsService` has no credit reserve, no usage row and no org attribution, and `kb-rag.service.ts` embeds the anonymous question *before* any credit check, so an org at zero credits still pays for every public question; a 20s timeout and 64-item batching were added here, but real metering needs an `orgId` threaded through 10 call sites, three of them outside S10. (ii) **there is no per-tenant in-flight concurrency cap** — the 30/min rate limit bounds the window, not simultaneity.
- [x] Prove prompt-injection, SSRF, tool-argument and data-exfiltration controls, structured output/citation integrity, tenant-safe AI caching and redacted metrics. — tool arguments are Zod-validated by the SDK against per-tool `inputSchema` before `execute`, tool names come from trusted module factories and are further narrowed by persona filtering, and no tool in scope takes a URL, so there is no SSRF surface to guard. Structured output goes through `withStructuredOutput(..., { strict: true })` and is re-parsed with the Zod schema; a `ZodError` releases the reservation and returns `invalid_output` rather than a half-answer. Citations are safe by construction on the client: citation buttons carry a numeric `data-page-id`, never a server-supplied URL. Prompts are redacted by default before dispatch and no logger or audit call in the gateway interpolates prompt text — only `promptKey`/`promptVersion`/token counts. **Two exfiltration paths closed.** (a) **AI-drafted email was injected into HTML unescaped** — the `email.send` and `mail.send` confirmed actions built `` `<p>${bodyText}</p>` `` straight from model output and sent it to an **external** recipient, so a poisoned KB page could steer the model into emitting a tracking pixel or active markup; both now escape through the shared `escapeHtml`, pinned by a boundary spec that fails if any future AI email path interpolates an unescaped value. (b) **the AI response cache was unsafe by default** — `aclVersion`, `sourceRevision` and `policy` were all optional and the `cache: true` shorthand resolved to `{}`, so the key was org + feature + tier + prompt-hash with **no reader dimension**: two users in one org asking the same question would share an answer built from documents only one of them could read. `aclVersion` is now a required field, the ACL-blind shorthand is deleted, and a runtime guard refuses an empty value — the unsafe state is unrepresentable rather than merely discouraged. Also fixed while there: a failed invocation was written to the cache, so one provider blip was served for an hour. Note the cache currently has zero callers; these changes make the first caller safe rather than fixing a live leak.
- [ ] Verify streaming, cancellation, partial/error/credit/provider states and permission changes without duplicate paid requests; run realistic-corpus focused performance tests. — **partially proven; three residues.** The chat assistant streams properly: `streamText` with a combined abort signal (client `res.on("close")` + a 120s deadline), TTFT recorded on first chunk, settle-on-finish with real token counts, release-on-abort, and a `resolved` flag that makes settle and release mutually exclusive so a cancelled stream is never both charged and refunded. Credit exhaustion returns 402 before any provider call and the page/article AI surfaces render a dedicated quota state. Frontend duplicate-request risk was reduced by gating the AI menus on `kb:ai:generate` so an unpermitted user no longer fires a guaranteed 403. **RESIDUE:** (i) **KB ask and the page/article AI actions do not stream at all** — they are single `useMutation` POSTs, so "first visible streamed state within 100 ms" is met only by the chat assistant; (ii) **the settle/release race is real but benign** — `onFinish` and `stream.finishReason.then(...)` both fire at stream end and race on `resolved`, so a completed stream is nondeterministically settled *or* refunded (never both); it under-bills rather than over-bills, which is why it was left rather than restructured blind; (iii) **realistic-corpus latency was not measured** — that needs a seeded database and `EXPLAIN` as `streamline_app` with the tenant GUC, the repo-wide deferred runtime-measurement item, not an S10 code gap.

- ~~**Settle and release race at stream end.**~~ **FIXED, and the policy is now explicit.** `stream.finishReason.then(...)` no longer releases on *success* — only its `.catch()` arm survives, for abort-before-any-output. So: normal completion settles with real tokens; abort before output releases the reservation (the pre-existing, spec-pinned refund policy, deliberately unchanged); mid-stream abort settles the partial usage `onFinish` reports and the later rejection is a no-op behind the guard. Determinism is proven by two tests that resolve `finishReason` before and after `onFinish` and assert the same billing outcome either way. Bite-proven by re-adding the `.then()` release.
