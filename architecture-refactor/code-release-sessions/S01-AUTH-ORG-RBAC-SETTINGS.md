### Two measurement traps hit in this session

1. **A stale jest transform cache reads as a boot failure — three times in one session.** The first S01 e2e run reported 7 suites dead with `ReferenceError: channelListQuerySchema is not defined` at `chat-channels.controller.ts:65`; the last reported `ReferenceError: chunks is not defined` at `kb-attachment-indexing.service.ts:253`, where `chunks` is declared 28 lines above in the same function. In every case the symbol exists in current source, and `--no-cache` passes. The tell is that the file belongs to a module another session is actively editing — the cache holds their pre-edit compilation. A `ReferenceError` at module load is not evidence of a defect until the cache is cleared; the cheap discriminator is one suite with `--no-cache`.
2. **`check:query-signal` is blind twice over, and its "0 violations across 399 files" is checked in the master PRD.** First, `apiClient.get` is `(url, params?, signal?)` with `params` typed `object`, so `apiClient.get<T>(url, signal)` typechecks, passes the gate, and never cancels — **26** reads do this. Second, the gate reads only a 150-character window after each `queryFn:` and skips the queryFn if no `apiClient` call appears inside it, so every multi-line body is invisible; a full-body parse of all 1,038 queryFns found **48** unseen, **47** of which destructure no `signal` at all. S01 fixed its 6 (2 positional, 4 windowed); ~69 non-cancellable reads were being concealed in total. A gate's headline number is a statement about what it inspects, not about the code.
