**Why committing became urgent — a shared-tree incident worth recording.** After this session's first verification pass, another session ran a checkout/restore inside `backend/`. Every *tracked* S04 edit was silently destroyed while the *untracked* new files survived, which left the module in a state that could not compile: seven new spec and helper files referencing symbols that no longer existed. The lesson for the orchestrator: **in a shared tree, verified work is not safe until it is committed**, and the failure is asymmetric — untracked files survive a restore, tracked edits do not, so a half-reverted module looks like a broken session rather than an external event.
