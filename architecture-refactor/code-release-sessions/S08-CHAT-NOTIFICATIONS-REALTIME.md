## Second pass — the eight open items

All eight were closed in-session. None needed a decision from the repo owner.

1. **Chat message send now has a durable client idempotency key.** Migration `0980` adds a nullable `client_key` and a PARTIAL unique index on `(org_id, channel_id, client_key) WHERE client_key IS NOT NULL`, so existing rows are untouched and callers that omit the key keep prior behaviour. `send` returns the original message on replay, and a race that gets past the pre-check collides on the index and replays the winner rather than failing. Evidence `__tests__/chat-send-idempotency.spec.ts` (5 tests); bite-checked by deleting the pre-check, which fails 3 of 5.
2. **`messages/poll` is cursor-paged.** It keysets on `channelPosition` (the same column history uses, served by `idx_chat_messages_channel_position`) and returns `{ messages, nextCursor, hasMore }`, so a client offline past one page can tell and can drain the gap. The 100-row silent truncation is gone. Evidence `__tests__/chat-poll-pagination.spec.ts` (6 tests); bite-checked by inverting the cursor comparison.
3. **Chat attachment access is re-authorized.** The finding is now established, not open: chat uploads use folder `"chat"`, which is absent from `PRIVATE_HR_FOLDERS`, so `publicUrlFor` minted a **permanent unauthenticated R2 URL** that was persisted in `chat_attachments.fileUrl` and served in message lists — access survived leaving the channel and leaving the organization. `GET /chat/channels/:channelId/attachments/:attachmentId` now asserts channel membership at the data layer and returns a 1-hour signed URL; the frontend renders through it. Private-channel denial is 404, public is 403. Evidence `__tests__/chat-attachments.spec.ts` (7 tests); bite-checked by removing the membership assertion. **The other half belongs to S12** — see below.
4. **Provider responses are Zod-validated and fail closed.** `providerSendResultSchema.safeParse` wraps `provider.send`; a response that does not parse is retried, never marked `SENT`.
5. **The delivery worker is per-organization fair.** `ORG_BATCH_CAP = ceil(BATCH_SIZE / 5)` caps one organization at 10 of the 50 slots per tick. Unclaimed rows stay `PENDING` and are claimed next tick, so nothing is dropped; the cap is computed before the first `await`, so it cannot be read pre-increment.
6. **`listMembers` is cursor-paged** on `asc(id)` with the page size capped at `PAGE_SIZE_CAP`, returning `{ members, nextCursor }`.
7. **The notifications page has an offline state**, matching chat's warning stripe, with a `role="status"` live region. A new shared `useOnlineStatus` hook replaces chat's inlined online-state effect.
8. **`chat_channels` can no longer disagree with itself.** This turned out worse than recorded: `assertMember` picks 404-vs-403 from `is_private`, and `createChannel` set it only for `type='PRIVATE'` — so a DIRECT message and an invite-only GROUP were stored `is_private=false` and **a non-member probing a DM was answered 403, confirming the conversation exists**. Migration `0981` backfills `is_private = (type <> 'PUBLIC')` and then adds a CHECK, and the create paths derive privacy from discoverability. Evidence `__tests__/chat-channel-privacy-invariant.spec.ts` (4 tests); bite-checked.

### Migration verification

Both migrations were executed against the live schema inside a transaction that was then rolled back, so the live database is unchanged. `0980`'s unique index was proven to bite (a duplicate `client_key` raised **23505**) and `0981`'s CHECK was proven to bite (`is_private=true` on a `PUBLIC` channel raised **23514**, while a consistent `GROUP` + `is_private=true` was accepted). Journal entries were added above the database watermark (`1803000010025`) so neither can be silently skipped.
