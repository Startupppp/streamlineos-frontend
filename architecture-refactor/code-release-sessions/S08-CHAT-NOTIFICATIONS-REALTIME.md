## Open items handed to the master backlog

Named rather than silently dropped. None is a regression from this session.

1. **Chat message send has no client idempotency key.** A send whose response is lost inserts a duplicate on retry; there is no `clientKey` and no unique constraint to enforce one. The fix needs a new unique index, which is **S02's schema lane**, plus the DTO and service change here.
2. **`messages/poll` truncates at 100 with no cursor.** A client offline past 100 messages silently loses the gap and cannot detect it from the response. Needs either a cursor on poll or an explicit truncation signal, plus the matching client fallback.
3. **Attachment access is unestablished.** `chat_attachments.fileUrl` is stored verbatim from the request body. Whether those are short-lived signed URLs or permanent object URLs cannot be determined inside the chat module; if permanent, possession of a URL outlives channel membership. Needs a decision with the storage owner (S12).
4. **Provider responses are not schema-validated.** `ProviderSendResult` is a TypeScript interface only; a malformed provider response degrades gracefully rather than being rejected at the boundary. No false-positive `SENT` is reachable today, so this is hardening, not a defect.
5. **No per-organization fairness in the delivery worker.** `forEachOrg` is sequential and the batch quota of 50 is global, so one large tenant can fill a tick. Durability is unaffected; latency for small tenants is not bounded.
6. **`listMembers` still returns at most 100 members with no cursor.** Order is now deterministic, but a channel with more than 100 members cannot page. Changing the shape touches the controller and the client and was left out of this batch.
7. **The notifications page has no offline state**, where chat has one (`message-panel-view.tsx`).
8. **`chat_channels` carries both `is_private` and `type = 'PRIVATE'`** and different services branch on different columns. No invariant keeps them in step. Schema-level fix belongs to S02.
