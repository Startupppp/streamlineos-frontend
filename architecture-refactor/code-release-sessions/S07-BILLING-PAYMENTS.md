- `subscriptions` has no `uniqueIndex(org_id)`, so two active rows for one org are representable and `findFirst` picks non-deterministically (`db/schema/common/subscriptions.ts:24-29`); `platformSubscriptions` shows the correct shape at `platform.ts:138`.
- `affiliates.referralCode` and `affiliates.userId` are globally `.unique()` — one tenant's value blocks every other org (`db/schema/billing/billing.ts:196,199`).
- `affiliateCommissions.affiliateId` is a bare scalar FK, so a commission row can point at another org's affiliate (`billing.ts:224`).

- Free-text status/type columns on financial tables (`subscription_payments.status`, `billing_invoice_snapshots.status`, `billing_credit_notes.status`, `billing_usage_reservations.status`, `affiliates.commissionType`) have no enum or CHECK.
- 13 billing tables still carry a single-column tenant FK reported by `check:tenant-relationships`. For `billing_credit_note_lines`, `billing_invoice_line_snapshots` and `billing_credit_notes` the composite FK is already declared in the schema and the single-column one is a residual the migration never dropped; `dunning_attempts → subscriptions` and `payment_* → payment_providers` are genuinely single-column. `coupon_redemptions → coupons` cannot take a composite while `coupons.org_id` stays nullable for platform-wide coupons — that is a design decision, not a mechanical repair.

## Corrected finding — there is no PAST_DUE downgrade defect

An earlier audit pass reported that `PlanLimitsService.queryTier` maps `PAST_DUE` to FREE through its final fallback, collapsing a paid org to FREE limits on the first failed renewal, and I recorded it as an open pricing decision. **Re-reading the control flow, that is wrong.** The status branch returns FREE only for `EXPIRED`/`CANCELLED` and expired `TRIAL` (`plan-limits.service.ts:137-146`); a `PAST_DUE` row with a real plan falls through to the plan branch and returns `PAID` (`:149-157`). The fallback is reached only when `plan` is not one of STARTER/PROFESSIONAL/ENTERPRISE. The grace period already works as the dunning ladder implies, and it is bounded: the D+14 sweep sets `status: "CANCELLED"` (`cron-billing.service.ts:271-285`), which *is* the branch that returns FREE. The abuse path is closed too — `transitionToPastDue` only moves a subscription that is already `ACTIVE` (`billing-payment-state.ts:94`), so a first-payment failure never reaches PAST_DUE. Both behaviours are now pinned by tests in `plan-limits.service.spec.ts` so the fallback cannot silently start catching PAST_DUE. Nothing is open here and no decision is required.
