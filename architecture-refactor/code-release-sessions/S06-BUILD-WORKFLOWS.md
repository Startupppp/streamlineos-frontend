## New gate

`check:unjoined-table-refs` (`src/scripts/check-unjoined-table-refs.mjs`) closes the defect class this session found. In Drizzle, referencing a table a query never joins compiles under TypeScript and then either names a table with no FROM entry (42P01) or — in a relational `findFirst` — is silently rewritten onto the root alias and reads a column that does not exist (42703). Four live instances existed; tsc, madge, knip and the unit suites were green on every one, because specs mock the db and never render SQL. The gate scans 2,982 files / 5,372 queries and skips 294 fragments it cannot resolve statically (correlated subqueries, `with:` clauses, CTEs), reporting that count rather than counting them clean. Its self-test carries all three broken shapes and their fixed counterparts, so it cannot pass without biting. Precision was measured, not assumed: the first draft reported 219 findings, all but one of which were false positives, and each cause was fixed until only the real one remained.

## Defects found and fixed

1. **`checkProjectAccess`'s team branch was invalid SQL.** It compared `projectTeamMembers.membershipId` to `organizationMembers.id` with `organization_members` in neither FROM nor JOIN. Rendered SQL confirmed 42P01. Every caller who was not an org owner, not `build:manage`, not the project manager and not a *direct* member reached that query, so `listTickets` and `deleteTicket` returned 500 instead of a clean 403 — and a team-only member could never load a board.
2. **`bulkUpdate`'s membership check read a column that does not exist.** The relational `findFirst` rewrote the foreign columns onto the root alias, rendering `"projectMembers"."membership_id" = "projectMembers"."id" and "projectMembers"."user_id" = $2`. `project_members` has no `user_id`, so bulk ticket update raised 42703 for every non-owner. It also lacked an `orgId` predicate.
3. **`searchOrgTickets` carried the same unjoined reference**, so org-wide ticket search failed for everyone.
4. **`getColumnCounts` had no access check at all.** Any holder of `build:tickets:view` could read the ticket-status distribution of a project `listTickets` refused them. It now runs the same gate and DataScope clause as the list, so the counts match what the caller can see.
5. **Thirteen Build services gated on existence rather than membership** — the BOLA described under the authorization criterion above.
6. **Roadmap, feedback and changelog accepted cross-tenant foreign keys.** `createRoadmap`/`updateRoadmap` wrote a client-supplied `projectId` and `epicTicketId`, and the feedback and changelog writers wrote `linkedRoadmapItemId`, without confirming the target belongs to the caller's org — the check `projects-write.service.ts` already applies for `managedProductId`. Six write paths now validate through `build/core/roadmap-references.ts`.
7. **The board cursor no longer matched its own sort** — see the contracts criterion. `board-keyset.spec.ts` caught this itself; it was a failing test reporting a real regression, not a stale double.
8. **Sprint bulk operations fanned out one PATCH per ticket.** Three `Promise.all` loops issued N independent requests with no atomicity, so a partial failure left the sprint half-moved. All three now use the bounded transactional bulk endpoint, chunked at its cap of 100. The same handler sent `sprintId: undefined` for "move to backlog", which `JSON.stringify` drops — so completing a sprint silently left its unfinished tickets attached. It sends `null` now.
9. **The Workflows module-disabled e2e asserted a paywall that cannot exist.** Workflows is registered `planGated: false`, so `isCoreModuleKey` makes it always available and `@RequireModule("workflows")` can never return 402. The tests now assert the real contract — a free module is not paywalled, but permission is still enforced — rather than being deleted.
10. **Eleven stale test doubles** across Build, broken by source changes that landed from other lanes during the session. Every one was repaired by teaching the double the query its service now runs; none was fixed by weakening an assertion. Two assertions were obsolete rather than stale — `project_members` has no `user_id` and `tickets` has no `assignee_id`, both dropped when the membership migration finished — and were rewritten to assert the finished state, so re-adding either column now fails the test.
