## What changed and why

**A gate reported "0 violations across 399 files" while 125 reads could not be cancelled.** `apiClient.get` was `(url, params?: object, signal?: AbortSignal)`, and an `AbortSignal` *is* an `object`, so `apiClient.get<T>(url, signal)` typechecked, satisfied the gate and cancelled nothing. The durable fix is not the call sites: `params` is now `QueryParams`, a union of an index-signature record and `object`, both intersected with `{ aborted?: never; addEventListener?: never; throwIfAborted?: never }`. Object literals, interfaces, `Record<string, unknown>` and `Record<string, string>` all stay assignable; an `AbortSignal` does not. **Proven against the shipped type, not a model of it** — a probe file compiled in-tree, `apiClient.get<string[]>("/things", signal)` failed with TS2345 while the three-argument form compiled, and the probe was then deleted.

**The gate had two more blind spots, and both were larger than the one already recorded.** It read a fixed **150-character window** after each `queryFn:`, so any multi-line body put the call out of scope, and it only asked whether the body *mentioned* `signal`. It now parses the whole arrow body — block or expression — and resolves every argument by **position**, reporting four distinct kinds: `MISSING_PARAM`, `NOT_FORWARDED`, `WRONG_SLOT` and `NO_SIGNAL_SLOT`. That turned "0" into **125 real violations**: 39 queryFns never destructured `signal`, 85 destructured it and never forwarded it, and one passed it as a **POST body**. All 125 are repaired.

**Writing the parser exposed three parser bugs of the same family, each caught by a fixture rather than by luck.** A comma inside `filters as Record<string, unknown>` split one argument into two, so 44 correct call sites were reported as wrong-slot. A cast spread across lines (`as Record<\n string,\n unknown\n>`) did the same. A nested generic (`CursorResult<Row, string>`) truncated the body. Angle-bracket depth is now tracked, with the discriminator that a type-argument list opens with `<` glued to an identifier and followed by something that starts a type — so `page < total` is left alone. Every one of these shapes is now a self-test fixture.

**`useChannelInviteLink` was sending an AbortSignal as a request body.** `apiClient.post(url, signal)` put the signal in the `data` slot, so `POST /chat/channels/{id}/invite-link` — an operation the contract marks `x-bodyless: true` — was serialising `{}` as its body and never cancelling. Fixed to `(url, undefined, { signal })`.

**The command catalog was a hand list; it is now derived from the contract.** The old classifier asked whether a hook *mentions* `useAuthorizedMutation` or hits a `/me/`-shaped path, and tracked a 677 drift baseline. It now resolves each hook's `apiClient` call to an operation in `contracts/openapi.json` and lets `x-exposure`/`x-permission` decide, so **no permission key was chosen by a person** — the recorded trap of guessing identifiers does not apply. 979 hooks were migrated to `useAuthorizedMutation` with their exact contract key; the frontend `PermissionKey` union accepted all of them, which is independent evidence that the keys are real.

**The old catalog could not see 382 of the hooks it was counting.** It matched `useMutation(`, and the dominant form in this repo is `useMutation<T, E, V>({…})` — 382 of 463 raw call sites. The 677 baseline was therefore measured by a scanner blind to a quarter of the population. Two further blind spots went with it: an `export const` arrow one-liner borrowed the *next* declaration's body, and **an apostrophe in a code comment** ("the person's own task list") put the argument parser into string mode and hid a hook's declared key. Comments are now blanked offset-preserving before parsing, and all three shapes are fixtures.

**Three permission keys were wrong, and one class of them blocks the very role the feature exists for.** `useApproveStage` and `useRejectStage` declared `payroll:runs:manage` while `payroll-approvals.controller.ts:89,123` requires `payroll:runs:approve` — a payroll approver holding only `:approve` was refused by the UI. `useExportTaxReport` declared `payroll:tax:manage` against `tax-admin.controller.ts:82`'s `payroll:reports:export`. All three verified in the backend source, not just in the contract, before changing. Twelve further hooks declare a *stricter* key than the route requires; loosening them would widen the UI past the product rule, so they are recorded in `STRICTER_KEYS` with the contract key as the value — which makes the entry go stale the moment the backend gate changes.

**`useAuthorizedMutation` treated "access not loaded yet" as "denied".** It read `useCan`, a boolean, while `permission-gate.ts` exists precisely to distinguish `pending` from `denied` — its own doc comment says "a screen that reads an unresolved gate as a refusal tells a permitted user they lack access". With 1,422 hooks now behind this seam, a user who clicked before `/me/access` resolved would have been told they lack permission. The guard now resolves the snapshot first and only then decides. It reaches for one extra module symbol (`useAccess`) rather than two, which kept the blast radius on existing test doubles to 14 files.

**There was no shared optimistic implementation; every domain re-derived one.** `lib/optimistic-cache.ts` provides `cancelAndSnapshot`/`restoreSnapshot` plus shape-aware `patchRows`/`patchRow`/`removeRow`/`patchDetail`/`patchCount` covering flat arrays, `{ data }` and `{ items }` cursor pages, and `InfiniteData` over any of them. An unrecognised shape is **left untouched rather than guessed at**, so the failure mode is "no optimistic update", not a corrupted cache. Fifteen tests cover every shape, cross-shape atomic updates, rollback across several filters, and concurrent realtime delivery composing with an in-flight patch. **The tests were proven to bite**: patching only page 0 instead of every page turned 2 of them red, and restoring the source turned them green.

**A local key factory could hardcode the cache prefix.** 66 sites across 26 files wrote `["streamlineos", …]` instead of composing `queryKeyBase`, so a change to the base would have applied to half the cache and silently split every affected key space. All 66 now spread `queryKeyBase`, and `check:query-scope` rule 5 forbids the literal outside `lib/query-keys/**`, with two known-bad and two exempt fixtures.

**Four shell primitives were missing.** There was no `app/global-error.tsx`, so a throw in the root layout had no fallback at all. Every `error.tsx` retry called Next's `reset()` without touching the query cache, so the entry that caused the error survived the retry and reproduced it — retry now calls `queryClient.resetQueries()` first, which refetches active queries while leaving unrelated hydrated data alone (`clear()` would have wiped another tenant's hydrated payload). `useOnlineStatus` existed but was consumed only by the notifications page and the barcode scanner, so the shell had no offline state — `ShellOfflineBanner` now renders one with `role="status"`. And nothing moved focus after an App Router navigation, so the skip link and `#dashboard-content` were decorative for keyboard and screen-reader users; `useRouteFocus` moves focus with `preventScroll`, skipping the first render. TanStack's `onlineManager` was deliberately **not** re-wired: v5 already installs the same `online`/`offline` listeners on first subscribe, so the wiring would have been dead code.

**Four shared-shell imports were loaded on every authenticated route to serve one route each.** `ChatMobileBottomNav` (rendered only on chat routes), `ProjectNavTree` (only inside a Build project), and `LeaveOrganizationDialog`/`ArchivedOrgsRestore` (only once the org switcher panel is open) were all module-scope imports in the client shell. Each is now `next/dynamic` with `ssr: false`. `LeaveOrganizationMenuItem` was deliberately left static: it renders a Radix `DropdownMenuItem`, and Radix builds its keyboard focus ring synchronously when the menu opens, so deferring it would break arrow-key navigation. No animation, visual or framer-motion usage was touched.

## Still open in this session's scope

- **`/inbox` bundle and authenticated Web Vitals are unmeasured since the change.** Four module-scope imports left the shared shell, but `route-bundle-manifest.json` and the Web-Vitals figures both predate that edit, so both gates are still RED on stale numbers. No budget was raised. Closing them needs `next build && next start` plus a fresh capture, which this criterion reserves for the orchestrator. The recorded arithmetic still stands as the shape of the problem: only 4 of `/inbox`'s 42 chunks (13,519 bytes) are inbox-specific and the shared shell was 545,161 bytes, over the 524,288 ceiling on its own — so the shell is the only place the excess can come from, which is where these four deferrals were made.
- **Mobile INP is an application finding, not an artifact.** It is entirely `/inbox` (416ms) and `/dashboard` (352ms), where ~1s long tasks block the main thread after FCP under 4× CPU throttle. Deferring shell modules should reduce parse and execute time on both, but that is a prediction until re-measured, and it is recorded as one.
- **Contrast and the 375/768/1280 sweep were not verified.** The shell's breakpoint strategy was read (a single `md` split at 768px, with `MobileShellFab`, `MobileModuleBottomNav` and a bottom-sheet drawer below it, plus `env(safe-area-inset-bottom)`), and `check:colors` is green on token usage — but measured contrast ratios and real viewport behaviour need a browser.
- **Browser E2E was not run**; no environment was available. Every result recorded here is from unit/component tests, gates and typecheck.
- **`check:over-300` is RED at 521 against a 519 baseline, and it is not this session's.** Proven rather than asserted: the over-300 set was computed for every `.ts`/`.tsx` file in the working tree and for the same paths at `HEAD` — **525 at HEAD, 525 in the working tree, 0 added, 0 dropped**. No file this session touched crosses the limit; the baseline is stale with respect to `HEAD`. Handed to the orchestrator.
- **Local key factories still live beside their features.** All 66 hardcoded prefixes now compose `queryKeyBase` and rule 5 keeps them that way, but roughly 20 domain files still define their own `*Keys` object rather than being enrolled in `lib/query-keys/**`, so the exhaustive registry walk in `query-keys-registry.test.ts` does not cover them. Moving them is domain-session work; the prefix being canonical is the part S11 owns.
