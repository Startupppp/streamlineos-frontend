# Migration And Rollout

## Migration Strategy

If existing project/task data exists:

- Map old projects to new projects.
- Map old tasks to work_items.
- Map old statuses to workflow statuses.
- Map old comments/files.
- Preserve IDs where possible.
- Mark migration source.

## Rollout Phases

### Phase 1

Projects, tasks, workflows, boards, comments.

### Phase 2

Sprints, QA, bugs, releases.

### Phase 3

Automation, chat, forms, approvals.

### Phase 4

Client portal, budget, time, resources.

### Phase 5

Reports, AI, portfolio/governance.

## Edge Cases

- Old status has no mapping.
- Task has missing project.
- Duplicate task IDs.
- Client-visible flag unknown.
