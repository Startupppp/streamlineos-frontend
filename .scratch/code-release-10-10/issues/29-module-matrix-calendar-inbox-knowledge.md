- [ ] **Knowledge queries/workers:** revision and search plans, ingestion leases with retry and DLQ, chunk dedupe, permission-aware cache keys, purge and reindex.
  Partially closed. **Permission-aware cache keys** is the box below and is done. The rest lives in `modules/kb/retrieval/**`, held by ticket 10 for the duration of this session — audited read-only, not modified.
  Verified satisfied: lease TTL 300s with a Lua compare-and-delete release (`kb-ingestion-lease.service.ts:6,7-8,30,52`); retry with exponential backoff capped at 60s and dead-lettering at 8 attempts (`common/outbox/outbox-envelope.ts:8,38-46`, `outbox-publisher.service.ts:210-245`); chunk dedupe hashes the **source** text, not the rejoined chunks (`kb-indexing.service.ts:180,289` via `kb-chunk-utils.ts:4-6`), skips re-embedding on an unchanged hash, and updates ACL columns in place when only the ACL moved; purge-on-soft-delete, de-index-on-archive and reindex-on-restore all present with covering specs.
  NOT satisfied, for whoever owns retrieval next:
  - **The lease fails open.** `kb-ingestion-lease.service.ts:24-25` and `37-43` both `return { token: "", acquired: true }` when Redis is absent or erroring, so every duplicate delivery indexes concurrently with no dedupe.
  - **Lease contention burns the retry budget.** `KB_CONCURRENCY_LIMIT` and `KB_INGESTION_LEASE_CONTENTION` are thrown as ordinary errors (`kb-ingestion-consumer.ts:65,95`), so a heavily-edited page can dead-letter after 8 contentions without ever failing to index.
  - **`kb.content.delete` is dead code.** `KbIngestionDeleteConsumer` implements a full four-way durable purge; nothing anywhere emits that event. Purging depends entirely on in-request `tx.delete` calls that are not outbox-backed.
  - **A space-property ACL change bumps `acl_revision` but never reindexes.** `kb-spaces.service.ts:186-201` bumps every page and article in the space and calls neither `syncAclRevisionForSpace` nor any `kb.content.index` emit (unlike `kb-members.service.ts:128-148`). The retrieval join is an `innerJoin` on equal revisions, so it fails *closed* — but permanently: after changing a space's audience or default visibility, its whole content silently disappears from vector search until some unrelated edit re-indexes it. No spec covers this.
  - **Search plan split-brain.** `kb-search.service.ts` correctly goes through `app.search_kb_article_ids` (SECURITY DEFINER, org from `app.current_org_id()`, ids only, capped) over the `idx_kb_articles_fts` GIN index.
