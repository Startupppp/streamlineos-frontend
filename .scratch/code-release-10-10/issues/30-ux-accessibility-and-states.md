# 30 — UX, accessibility and responsive behaviour across authenticated surfaces

**What to build:** The §10.18 UX criteria: every state rendered, every surface keyboard- and screen-reader-navigable, and correct layout at the three reference widths.

**Blocked by:** 28.

**Status:** audited, measured and ratcheted — 2 of 7 closed. Full report: `reports/30-ux-accessibility.md`.

- [ ] Loading, empty, error, offline and permission-denied states are present on every authenticated surface, not only the common paths.
  NOT MET, now measured for the first time. `npx jest components/__tests__/authenticated-surface-states.contract.test.ts` → 19/19, reporting 556 authenticated route modules / 540 reading server state, of which **78 have no read-error branch, 56 no empty state, 2 no loading state, 1 no permission gate**; 101 files conflate filter-empty with data-empty. Offline is 0 missing — handled once in the shell. Ratchet installed so the counts can only fall.
- [ ] Keyboard navigation and screen-reader semantics work on every interactive surface; focus is managed across dialogs, drawers and route transitions.
  Focus-management half CLOSED: `npx jest components/ui/__tests__/overlay-focus.a11y.test.tsx` → 12/12 (Dialog/Sheet trap on open, restore to trigger on Escape, rest of page hidden from AT, ResponsivePopover = Drawer at 375 / Popover at 1280), plus `components/layout/__tests__` → 32/32 for skip link, route focus and the now-named `<main>`. Six real defects fixed (dead `sortable` control across 197 columns, unnamed `LoadingState`, silent DataTable loading, announced skeletons, h1→h3 heading-order break, unnamed `<main>`). The "every interactive surface" claim across 556 pages is not established by 61 component tests, so not ticked.
- [ ] Contrast meets the standard and is verified rather than assumed.
  VERIFIED: `npx jest components/ui/__tests__/contrast-tokens.test.ts` → **41/41** (was 13). Fixed a real WCAG 2.2 SC 1.4.11 failure — `--ring` 2.45:1 and `--sidebar-ring` 2.54:1 are now 3.52:1 / 3.68:1. Also fixed the file's light/dark block split, which read every token after line 148 out of the wrong block. NOT fully met: `--status-success-ink` 3.58, `--status-warning-ink` 3.07, `--status-danger-ink` 4.41 and `--muted-foreground`-on-`--muted` 4.34 are all below AA 4.5 for normal text; `-ink-strong` passes everywhere (5.21 / 4.84 / 5.91). 2134 call sites — a token-layer decision, not a session's.
- [ ] Layout is correct at 375, 768 and 1280.
  BLOCKED: jsdom has no layout engine, so overflow, wrapping and intersection cannot be computed and "correct" is unprovable here. Needs a real browser or visual-regression harness. What IS proven at the three widths (`npx jest components/ui/__tests__/page-states-responsive.a11y.test.tsx` → 30/30): axe passes for loading, empty, error and denied; exactly one `h1`; the filter row carries no wrap class; the stat row keeps its scroller and never gains `md:overflow-x-visible`.
- [ ] Representative browser end-to-end journeys cover the main module flows.
  BLOCKED: there is no browser harness in either repo — no `playwright` / `cypress` / `puppeteer` in `frontend/package.json` or the root manifest, no binary in either `node_modules/.bin`, no `playwright.config.*` or `cypress.config.*`, no `e2e/` directory, no `test:e2e` script. Closing this needs a harness added plus a running app, backend and seeded auth session, none of which exists here.
- [x] Error and offline states are not removed during cleanup merely because they are uncommon in local development.
  Closed by construction. The ratchet in `components/__tests__/authenticated-surface-states.contract.test.ts` fails the moment any surface loses its loading, empty, error or permission state, and four tests pin offline: the shell mounts `<ShellOfflineBanner />`, the banner is `role="status" aria-live="polite"`, the hook listens for both `online` and `offline`, and a bite proof fails if the banner is unmounted. 19/19 green.
- [x] Public metadata is correct without changing landing visuals or animations.
  `pnpm -s check:seo-metadata` exit 0 and `check:seo-metadata:self-test` passes. It enforces `robots: { index: false, follow: false }` on every authenticated layout, `title` + `description` + `alternates.canonical` on every intentionally indexable public page, and no auth-gated import inside `app/(public)`. `app/robots.ts` and `app/sitemap.ts` both exist. No file under `app/(public)/**` or `features/landing/**` was touched; `--ring` is focus-only on public surfaces (grep confirms no decorative use), so no landing visual or animation changed.
