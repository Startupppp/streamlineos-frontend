# 10 — Route embedding through the AI gateway and reserve credit before public KB embedding

**What to build:** Every AI feature reaches a provider through one backend gateway with centralized timeouts, usage accounting, policy and redaction. Embedding currently bypasses that interface, and public KB embedding calls a paid provider before reserving credit — on a route where the caller supplies the organization id, that is unmetered spend on anonymous traffic.

**Blocked by:** 09 — the limiter must be required first, or the new call sites inherit the fail-open shape.

**Status:** partially closed — 4 of 6 boxes; boxes 1 and 2 blocked on paths outside session S3's territory

- [ ] Embedding goes through the gateway interface, not a direct provider client. No frontend direct-provider calls exist.
  - Frontend half PROVEN: `package.json` declares no provider SDK (`openai`, `ai`, `@ai-sdk/*`, `@langchain/*`, `@google/generative-ai`, `@anthropic-ai/*` all absent) and a repo-wide grep for `api.openai` / `generativelanguage` / `openrouter` over `.ts`/`.tsx` returns **0** hits outside marketing copy.
  - BLOCKED (backend half): 7 call sites in 5 files still inject `EmbeddingsService` directly, all outside `backend/src/modules/ai/**` which is S3's exclusive territory — `kb/retrieval/kb-search.service.ts:143,251,298`, `kb/retrieval/kb-indexing.service.ts:107`, `kb/retrieval/kb-attachment-indexing.service.ts:32`, `support/core/support-ai-embeddings.helper.ts:36`, `support/core/support-ai-triage-data.service.ts:119`. The gateway side of the migration is done and tested; only the call sites remain. Needs an owner for `modules/kb/retrieval/**` and `modules/support/core/**`.
- [ ] Credit is reserved atomically **before** any paid call, including on public routes, and the reservation is settled against actual input/output usage.
  - CLOSED for every gateway path including embedding: `AiGatewayService.embedQueryWithCredit` now reserves before `embedQueryRaw` and settles on the estimated input tokens. `nice -n 10 npx jest src/modules/ai --maxWorkers=2` → **41 suites / 338 passed, 21 skipped**; the 3 ordering/short-circuit assertions go red when reserve is moved after the provider call (bite-proved: 4 failed / 6 passed).
  - Public routes proven: `POST /public/kb/ask` and `/public/kb/stream-ask` short-circuit on `hasPublishedPublicArticles` before any embedding (`ai-kb-blog-survey-tenant-isolation.spec.ts` — "embedQueryWithCredit never called"), then reserve for both the embedding and the completion.
  - BLOCKED: the same 7 direct-provider embedding call sites above take no reservation at all. Their features (`kb.search`, `kb.indexing`, `support.embedding`, `support.kb-search`) are also absent from `AI_FEATURE_COSTS`, so migrating them needs catalog entries or they inherit the 1-credit default ceiling per chunk.
- [x] Charges are token-metered via the token-charge computation, never flat per action; feature costs remain reserve ceilings only.
  - Proven: `AI_FEATURE_COSTS` has exactly one consumer, `getReserveEstimateMilli`, and every one of its 4 call sites is a `ledger.reserve` (grep over `src`, 0 other consumers). Every settle path computes `computeTokenCharge`. New test asserts a 1,000-token embedding settles **10** milli and a 10,000-token embedding settles **30** milli against a **1,000** milli reserve ceiling.
- [x] The ledger stores integer milli-credits; APIs emit fractional credits; under-run refunds and overage debits settle correctly.
  - Proven: `nice -n 10 npx jest src/modules/billing/core/ai-credits --maxWorkers=2` → **5 suites / 42 passed**, including "settles partially — refunds the difference when actual < reserved" and "charges overage — balance goes negative when actual > reserved". `milliToCredits` is the only API-facing conversion.
- [x] Refunds follow the documented failure contract — a cancelled or failed call never silently keeps the reservation, and never double-charges on retry.
  - Proven by the same 42-test run: settle is idempotent when already SETTLED, release is idempotent when already RELEASED, releasing a SETTLED reservation raises `ConflictException`, and `sweepExpiredReservations` releases only expired RESERVED rows. New embedding tests assert the reservation is released with reason `embedding_error` on provider failure and that a settlement failure neither refunds nor fails an embedding that already succeeded.
- [x] Deterministic RBAC and tenant/record ACL checks complete before retrieval or provider invocation; AI participates in no authorization decision.
  - Proven: every non-`@Public` AI route carries `@RequirePermission` (grep across all 12 AI controllers; the only `@Public` controller is `kb-rag.controller.ts`, whose ACL is the `published`/`visibility=public`/space-audience SQL predicate plus the pre-embedding `hasPublishedPublicArticles` gate). `grep` for permission/role table writes under `src/modules/ai` → **0**; `grep` for `modules/ai` imports from `modules/rbac`, `modules/auth`, `common/auth` → **0**. `ToolAccessService` resolves scope from `AccessService.resolveUserPermissions`, never from the model.
