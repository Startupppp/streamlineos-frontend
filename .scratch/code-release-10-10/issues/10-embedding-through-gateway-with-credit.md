# 10 — Route embedding through the AI gateway and reserve credit before public KB embedding

**What to build:** Every AI feature reaches a provider through one backend gateway with centralized timeouts, usage accounting, policy and redaction. Embedding currently bypasses that interface, and public KB embedding calls a paid provider before reserving credit — on a route where the caller supplies the organization id, that is unmetered spend on anonymous traffic.

**Blocked by:** 09 — the limiter must be required first, or the new call sites inherit the fail-open shape.

**Status:** all 6 boxes closed

- [x] Embedding goes through the gateway interface, not a direct provider client. No frontend direct-provider calls exist.
  - All 7 direct `EmbeddingsService` call sites migrated to `AiGatewayService`. `grep -rln EmbeddingsService src | grep -v spec` → **4 files, all inside `modules/ai/core/gateway|providers`**; zero consumers outside the gateway. `EmbeddingsService` was removed from `AiGatewayModule.exports`, and its three un-metered wrappers (`embedQuery`, `embedBatch`, `embedQueryDeduped`) were deleted — the class now exposes only `embedQueryRaw`, `embedBatchRaw`, `isConfigured`, `toVectorLiteral`, pinned by a test that asserts that exact public surface. There is no longer any way to embed without going through the credit path.
  - Frontend: `package.json` declares no provider SDK (`openai`, `ai`, `@ai-sdk/*`, `@langchain/*`, `@google/generative-ai`, `@anthropic-ai/*` all absent); repo-wide grep for `api.openai` / `generativelanguage` / `openrouter` over `.ts`/`.tsx` → **0** hits outside marketing copy.
- [x] Credit is reserved atomically **before** any paid call, including on public routes, and the reservation is settled against actual input/output usage.
  - Every embedding path now reserves before the provider call and settles on actual tokens: `embedQueryWithCredit` (single) and `embedBatchWithCredit` (batch, **one** reservation for the whole batch). Bite-proved twice — removing the batch reservation turns 4 tests red (`reserves ONCE for the whole batch`, `settles on the summed actual tokens`, `never calls the provider when the wallet is short`, `releases the reservation when the provider throws mid-batch`); restoring returns 39/39. Files restored and SHA-256 verified.
  - `kb-indexing.service.ts` no longer fans out one paid call per chunk: `nice -n 10 npx jest src/modules/kb --maxWorkers=2` → **122 suites / 848 passed** including `R1b: one reservation covers the whole document — the gateway is called once, not once per chunk`. Reverting to a per-chunk loop turns R1b and R3 red.
  - Public routes: `POST /public/kb/ask` and `/public/kb/stream-ask` short-circuit on `hasPublishedPublicArticles` before any embedding, then reserve for both the embedding and the completion.
- [x] Charges are token-metered via the token-charge computation, never flat per action; feature costs remain reserve ceilings only.
  - `AI_FEATURE_COSTS` has exactly one consumer, `getReserveEstimateMilli`, and all 5 of its call sites are `ledger.reserve`. Every settle path computes `computeTokenCharge`. Added the 4 missing ceilings — `kb.search` 0.05, `kb.indexing` 1, `support.embedding` 0.05, `support.kb-search` 0.05 — sized against the real worst case (`chunkText` caps a document at 400 chunks ≈ 150k tokens ≈ 450 milli, under the 1-credit ceiling). `getReserveEstimateMilli` now rounds so a fractional ceiling can never produce a non-integer milli amount.
  - Tests assert a 1,000-token embed settles **10** milli, a 10,000-token embed **30** milli, and a 10×4,000-char batch **30** milli on 10,000 summed tokens — none equal to the 1,000-milli ceiling.
- [x] The ledger stores integer milli-credits; APIs emit fractional credits; under-run refunds and overage debits settle correctly.
  - `nice -n 10 npx jest src/modules/billing/core/ai-credits --maxWorkers=2` → **5 suites / 42 passed**, including "settles partially — refunds the difference when actual < reserved" and "charges overage — balance goes negative when actual > reserved". `milliToCredits` is the only API-facing conversion.
- [x] Refunds follow the documented failure contract — a cancelled or failed call never silently keeps the reservation, and never double-charges on retry.
  - Same 42-test run: settle idempotent when SETTLED, release idempotent when RELEASED, `ConflictException` on releasing a SETTLED reservation, `sweepExpiredReservations` releases only expired RESERVED rows. Embedding tests assert the reservation is released with reason `embedding_error` on provider failure, and that a settlement failure neither refunds nor fails an embedding that already succeeded. `R1` and `R5` assert an indexing run that fails on the provider or on credit writes **no checkpoints and no chunks** — the failed attempt leaves no partial state and is fully refunded.
- [x] Deterministic RBAC and tenant/record ACL checks complete before retrieval or provider invocation; AI participates in no authorization decision.
  - Every non-`@Public` AI route carries `@RequirePermission` (12 controllers). `grep` for permission/role table writes under `src/modules/ai` → **0**; `grep` for `modules/ai` imports from `modules/rbac`, `modules/auth`, `common/auth` → **0**. `ToolAccessService` resolves scope from `AccessService.resolveUserPermissions`, never from the model. In `support-ai-triage-data.searchKbForTicket` and `kb-search.service`, `getAccessibleSpaceIds` / `getPrincipalIds` / the restriction predicate still run **before** the embed call.
