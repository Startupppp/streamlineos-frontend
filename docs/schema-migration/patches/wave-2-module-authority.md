# Wave 2 Patch Spec — `org_modules` as Sole Module Authority

## 0. The Verified Gap (A05 Finding)

Two code paths gate module access with incompatible defaults:

| Path | Guard | Store | Default when no row exists |
|---|---|---|---|
| A — `@RequireModule` | `ModuleGuard` (module.guard.ts:21) | `req.user.enabledModules` (sourced from `organizations.enabled_modules` text[]) | **DENY** — allowlist; absent = not enabled |
| B — `@RequirePermission` | `PermissionGuard` → `authorize.ts:20` → `entitlements.service.ts:132` | `org_modules` table via `isModuleEnabled` | **ALLOW** — `if (!(moduleKey in map)) return true` |

**Concrete consequence:** `org_modules` currently has 2 rows across 12 orgs (verified 2026-07-26). For every org that has a module listed in `enabled_modules` (Path A enforces it) but no row in `org_modules` (Path B allows it), a user whose role has a permission under that module can call `@RequirePermission`-only endpoints even if the module is conceptually disabled. This is a live A05 (Broken Function Level Authorization) gap.

**Why the backfill in Step 2 closes it:** After the backfill every org×module has an explicit `org_modules` row reflecting the array's current allowlist. `isModuleEnabled` then reads a row that exists and returns its stored `enabled` flag rather than the allow-on-absent default. The `if (!(moduleKey in map)) return true` branch at `entitlements.service.ts:132` becomes unreachable for any configured module.

## 1. Add Lifecycle Columns to `org_modules` (W2.1)

### What is wrong right now

`orgModules` schema (`backend/src/db/schema/access.ts`, lines 65–79):

```typescript
// BEFORE — current state (verified)
export const orgModules = pgTable(
  "org_modules",
  {
    id: uuid("id").defaultRandom().primaryKey(),
    orgId: text("org_id").references(() => organizations.id, { onDelete: "cascade" }).notNull(),
    moduleKey: varchar("module_key", { length: 64 }).notNull(),
    enabled: boolean("enabled").default(true).notNull(),
    enabledAt: timestamp("enabled_at").defaultNow().notNull(),
    enabledBy: varchar("enabled_by", { length: 36 }),   // no FK; raw user id varchar(36)
    // MISSING: disabledAt, disabledBy, archivedAt, archivedBy
  },
  (t) => [
    uniqueIndex("org_modules_unique_idx").on(t.orgId, t.moduleKey),
    index("org_modules_org_idx").on(t.orgId),
  ],
);
```

Three gaps:
1. `enabledBy` is `varchar(36)` with no FK to `users.id` (no referential integrity).
2. No `disabledAt` / `disabledBy` timestamps — disabling a module loses the audit trail.
3. No `archivedAt` / `archivedBy` — no soft-archive lifecycle for modules being retired.

### Drizzle schema — AFTER

Replace the `orgModules` definition in `backend/src/db/schema/access.ts`:

## 2. Backfill: Populate `org_modules` from `organizations.enabled_modules` (W2.2)

### Purpose

After this step every org×non-core-module pair has an explicit row in `org_modules`. The `isModuleEnabled` allow-on-absent default (`entitlements.service.ts:132`) becomes unreachable for any module in the catalog. Path A and Path B agree.

|---|---|---|
| `hr` | `HR` | |
| `crm` | `CRM` | |
| `projects` | `PROJECTS` | |

## 3. Switch `ModuleGuard` and `fetchOrgContext` to Read `org_modules` (W2.4)

This is the read-switch step. It comes after the 7-day shadow-compare window (W2.3 — dual-read telemetry; described in the execution plan, not duplicated here).

### 3a. `ModuleGuard` — before and after

**File:** `backend/src/common/rbac/module.guard.ts`

**Root cause of the gap:** `ModuleGuard` reads `req.user.enabledModules` which is populated from `organizations.enabled_modules` (the text array) — never from `org_modules`. Even after the backfill keeps them in sync, the array remains a stale secondary copy after W2.6 stops the dual-write.

**Option B (recommended — removes the array dependency entirely):** Inject `EntitlementsService` into `ModuleGuard` and call `isModuleEnabled` directly. The array lookup in `fetchOrgContext` is no longer needed for module-gating.

```typescript
// BEFORE (module.guard.ts — current)
@Injectable()
export class ModuleGuard implements CanActivate {
  constructor(private readonly reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const required = this.reflector.getAllAndOverride<string | undefined>(REQUIRE_MODULE, [
      context.getHandler(),
      context.getClass(),
    ]);
    if (!required) return true;

    const req = context.switchToHttp().getRequest<Request & { user: CurrentUserContext }>();
    const user = req.user;
    if (!user.isPlatformAdmin && !user.isOrgOwner && !user.enabledModules.some(m => m.toUpperCase() === required.toUpperCase())) {
      throw new ModuleDisabledException(required);
    }
    return true;
  }
}
```

```typescript
// AFTER (module.guard.ts — reads org_modules via EntitlementsService)
import { CanActivate, ExecutionContext, Injectable } from "@nestjs/common";
import { Reflector } from "@nestjs/core";
import type { Request } from "express";
import { REQUIRE_MODULE } from "./require-module.decorator";
import { ModuleDisabledException } from "../http/api-exceptions";
import type { CurrentUserContext } from "../auth/backend-claims";
import { EntitlementsService } from "../../modules/access/entitlements.service";

@Injectable()
export class ModuleGuard implements CanActivate {
  constructor(
    private readonly reflector: Reflector,
    private readonly entitlements: EntitlementsService,
  ) {}

  async canActivate(context: ExecutionContext): Promise<boolean> {
    const required = this.reflector.getAllAndOverride<string | undefined>(REQUIRE_MODULE, [
      context.getHandler(),
      context.getClass(),
    ]);
    if (!required) return true;

    const req = context.switchToHttp().getRequest<Request & { user: CurrentUserContext }>();
    const user = req.user;

    if (user.isPlatformAdmin || user.isOrgOwner) return true;

    const enabled = await this.entitlements.isModuleEnabled(user.orgId, required.toLowerCase());
    if (!enabled) throw new ModuleDisabledException(required);
    return true;
  }
}
```

**Key changes:**
- `canActivate` becomes `async` (returns `Promise<boolean>`).
- `required.toLowerCase()` normalises to the `org_modules.module_key` casing (`hr`, `crm`, etc.) — the array comparison used `toUpperCase()` which mapped to the vocabulary mismatch values (`FINANCE`, `HELPDESK`); the new path skips that mapping entirely.
- `EntitlementsService` must be registered in the same module that provides `ModuleGuard` (verify `RbacModule` or `AccessModule` exports it, or add it there).

**Vocabulary mismatch resolution:** `@RequireModule("accounting")` now looks up `org_modules` where `module_key = 'accounting'`, which exists after the backfill. Previously `ModuleGuard` compared `"accounting".toUpperCase()` (`"ACCOUNTING"`) against the array which stored `"FINANCE"` — this was a silent allow-all for accounting/finance module-gated routes. After this switch the correct row is found.

```typescript
// (EntitlementsService must be injected into JwtAuthGuard)
private async fetchOrgContext(userId: string): Promise<OrgContext | null> {
  const [user, rows] = await Promise.all([
    this.db.query.users.findFirst({ ... columns: { lastActiveOrgId: true } }),
    this.db
      .select({
        orgId: organizationMembers.orgId,
        role: organizationMembers.role,
        isOwner: organizationMembers.isOwner,
        // enabledModules removed from this select — no longer needed here
      })
      .from(organizationMembers)
      .innerJoin(organizations, eq(organizations.id, organizationMembers.orgId))
      .where(eq(organizationMembers.userId, userId))
      .orderBy(desc(organizationMembers.joinedAt)),
  ]);

  const preferred = user?.lastActiveOrgId
    ? rows.find((r) => r.orgId === user.lastActiveOrgId)
    : undefined;
  const member = preferred ?? rows[0];
  if (!member) return null;

  // Read module state from org_modules (the new authority)
  const moduleMap = await this.entitlements.getModuleMap(member.orgId);
  // Convert to UPPERCASE names for backward-compat with any remaining consumers
  // that read req.user.enabledModules as array strings.
  // MODULE_KEY_TO_ORG_MODULE is imported from entitlements.service.ts (export it).
  const enabledModules = Object.entries(MODULE_KEY_TO_ORG_MODULE)
    .filter(([key]) => moduleMap[key] !== false)
    .map(([, name]) => name);

  const subscription = await this.db
    .select({ plan: subscriptions.plan })
    .from(subscriptions)
    .where(eq(subscriptions.orgId, member.orgId))
    .limit(1)
    .then((r) => r[0] ?? null);

  return {
    orgId: member.orgId,
    role: member.role,
    isOwner: member.isOwner,
    enabledModules,   // now sourced from org_modules
    plan: subscription?.plan ?? null,
  };
}
```

## 5. How the Module-Gate Gap Closes — Step-by-Step

| Step | Before | After | Gap state |
|---|---|---|---|
| Today (baseline) | `org_modules` has 2 rows / 12 orgs. `isModuleEnabled` returns `true` for any missing row (allow-on-absent). `@RequirePermission`-only endpoints for any missing module are reachable. | — | **Gap OPEN** |
| After Step 1 (W2.1) | Lifecycle columns added. No behavior change. | `org_modules` has lifecycle columns; `enabledBy` FK validated. | Gap still open |
| After Step 2 (W2.2 backfill) | Every org×module has an explicit `org_modules` row. `isModuleEnabled` now always finds a row and returns its stored `enabled` flag. The `if (!(moduleKey in map)) return true` branch is unreachable for all 9 configured modules. | Path B (`@RequirePermission`) now enforces the same module state as Path A. | **Gap CLOSED for Path B** |
| After Step 3 (W2.4 read-switch) | `ModuleGuard` reads `org_modules` directly. `fetchOrgContext` populates `req.user.enabledModules` from `org_modules`. Both paths read the same store. Vocabulary mismatch (FINANCE vs accounting) is resolved — `@RequireModule("accounting")` now looks up `module_key = 'accounting'`. | Single source of truth. | **Gap FULLY CLOSED, single authority** |
| After Step 4a (W2.6) | Dual-write to `enabled_modules` removed. `org_modules` is the only written store. | — | — |
| After Step 4b (W2.7) | `enabled_modules` column dropped. | `org_modules` is the sole module authority in schema and code. | **Complete** |

**Critical ordering constraint:** Step 2 (backfill) MUST complete with zero parity mismatches before Step 3 (read-switch). If the read is switched before the backfill, orgs without `org_modules` rows would be treated as "module not in map → return true" by `isModuleEnabled`, opening Path B to all modules for those orgs. The backfill closes that window first.
