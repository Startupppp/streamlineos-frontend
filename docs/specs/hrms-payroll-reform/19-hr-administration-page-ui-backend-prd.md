# HR administration page UI and backend PRD

**Status:** Target-state specification; 48 canonical HR administration pages.  
**Scope and route priority:** [PRD 07](./07-pages-navigation-roles-prd.md). **Authorization:** [PRD 07a](./07a-page-permission-manifest-prd.md). **Common page behavior:** [self-service PRD 18](./18-self-service-page-ui-backend-prd.md#contract-applied-to-every-page-below) applies here as well. **Product ownership:** [00a](./00a-suite-domain-contracts-prd.md).

## Module-level RBAC contract

`HRMS` is its own module entitlement. An authenticated actor needs the enabled HRMS module plus the route's HR permission, scoped object relationship, action permission and field purpose. A Payroll entitlement or Payroll operator role grants no HRMS route by itself. An HRMS operator role grants no pay, tax, bank, payout or payroll-report fact. A cross-module HR page asks Payroll for a separately authorized, minimal projection such as `payroll readiness` or `FnF status`; a denial is displayed as unavailable, not as zero or complete. HRMS-only, Payroll-only, both-enabled and neither-enabled actors must be tested through sidebar, command palette, direct URL, API, export, cache, Calendar, chart and AskOS. Entitlement failure, permission failure, field denial and missing data have different UI states and backend error envelopes. The backend checks again at every read, command and download; frontend navigation filtering never substitutes for authorization.

## Completion rule

All 48 canonical rows need a reachable authorized destination, named owner, actual permission and field matrix, strict read/command contract, safe states and task-level evidence. Future P1 pages may remain disabled under an explicit entitlement; they must not appear as broken navigation. Existing routes that implement a job under another URL or need retirement are reconciled in [PRD 21](./21-supporting-page-route-disposition-prd.md). The [architecture execution ledger](./architecture-review/execution-ledger.json) and [PRD 06a](./06a-operations-release-evidence-prd.md) govern completion evidence.
