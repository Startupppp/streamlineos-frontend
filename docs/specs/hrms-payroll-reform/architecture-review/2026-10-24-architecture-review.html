Design discipline and migration safeguards

Depth: fewer facts a caller must know, with more business correctness behind the interface. File count and line ratios do not measure it. Locality: change, failure and verification concentrate with the fact owner. Leverage: one interface serves Payroll, Calendar, charts or AskOS without duplicating policy.

Seam and adapter: use an in-process interface for deterministic values and normalization. The current query-chain mocks are not a PostgreSQL stand-in. Database races require an isolated PostgreSQL fixture under the application role; do not introduce a generic repository module just to mock Drizzle. Third-party bank/storage adapters use mocks plus sandbox evidence. One speculative adapter does not justify a new port.

Deletion test: broad re-export barrels and pure forwarding modules can disappear when direct imports preserve behavior. Identity resolution, access decisions, snapshot validation, reconciliation and file lifecycle earn depth; deleting them only moves complexity to callers. Replace shallow tests with interface-level behavior tests only after equivalent scenarios are covered.
