# Self-service page UI and backend PRD

**Status:** Target-state specification; implementation evidence is separate.  
**Scope:** The 27 `/me` pages in [PRD 07](./07-pages-navigation-roles-prd.md).  
**Authority:** [Domain contracts](./00a-suite-domain-contracts-prd.md), [page permissions](./07a-page-permission-manifest-prd.md), [experience](./07b-experience-content-quality-prd.md), and owning domain PRDs.  
**Companion:** [HR pages](./19-hr-administration-page-ui-backend-prd.md), [Payroll pages](./20-payroll-page-ui-backend-prd.md), [settings/implementation and route disposition](./21-supporting-page-route-disposition-prd.md).

## Contract applied to every page below

The **UI item** names the visible sections, primary action, and essential exception states for that page. Every page also needs a clear title and purpose, actor-safe breadcrumbs, contextual help, last-updated/source status where facts can lag, keyboard/focus behavior, mobile priority, responsive widths 375/768/1280, light/dark tokens, and accessible error/retry, loading, disabled-module, denied, empty, filtered-empty, stale/conflict, partial and success states. Forms show required fields, validation, unsaved changes, preview of irreversible effects, and a final receipt. Sensitive values are masked until a separate field permission permits reveal. Search/filter/sort/tab state that users share or revisit belongs in the URL.

The **backend item** names the owner read model and commands; it is a contract, not a new parallel data store. Each read resolves the current tenant, active worker identity, entitlement, permission, DataScope and field policy before query/cache fill; lists use stable bounded cursors and a total/coverage statement where meaningful. Each command validates a strict versioned schema, effective date, expected record version, idempotency key, actor and object scope, and publishes audit plus durable downstream intent in the same transaction where required. Return typed success/conflict/denied/disabled/partial states. Cache keys and invalidation follow [architecture PRD 16](./16-architecture-hardening-prd.md). Files use authorize-before-metadata and authorize-again-at-download. Client query options share key, fetcher, envelope and invalidation policy with SSR. P0/P1 scope is inherited from PRD 07; the presence of a page contract does not accelerate a later-tier capability.

## Acceptance and ownership

For each of the 27 rows, the implementing agent must record: the actual route or hub/tab that delivers it, current source/owner, permission and field-policy test, contract and migration version, read/query and command tests, all common page states, a complete task test at required sizes/input modes, and any connected-provider evidence. A row is incomplete when its canonical route has no safe destination or its backend outcome cannot be observed/recovered. Current `/me/workday`, `/me/records`, `/me/money`, `/me/career` and `/me/support` hubs may host these jobs; [route disposition](./21-supporting-page-route-disposition-prd.md) records how the canonical job maps to the current URL without duplicating screens.
