## Outcome

Build meets the table-stakes expectations created by ClickUp, Linear, Jira,
Asana, monday.com, and Notion without copying their information architecture or
shipping duplicate features. StreamlineOS wins through coherent cross-module
workflows, evidence-backed agents, and client-ready progress.

Feature presence is not parity. A page counts only when authorization, scale,
errors, mobile, accessibility, lifecycle, and end-to-end customer outcome work.

## Evidence Policy

- use first-party product documentation for capability claims;
- record page title, URL, and review date;
- distinguish plan-limited, beta, marketplace, and native behavior;
- validate important flows in the actual product when access is available;
- do not infer implementation quality from marketing copy;
- reassess before release because competitor behavior changes.

## Baseline Capability Matrix

### Work Model and Navigation

- flexible organization/workspace/product/project hierarchy;
- fast switcher, recent/starred scopes, search, and keyboard navigation;
- issue hierarchy, relations, dependencies, modules/components, iterations,
  milestones, and releases;
- private, shared, and default views;
- templates and repeatable setup;
- guests and controlled external collaboration.

- [ ] **BLD-09-003** hierarchy remains understandable without mandatory
  enterprise layers for a freelancer.
- [ ] **BLD-09-004** every hierarchy link has explicit access and lifecycle
  behavior.

### Views and Discovery

- board, list, table, timeline;
- global My Work and cross-project All Work;
- rich filters with include/exclude, empty, dates, people, relations, and custom
  fields;
- saved, shared, pinned, and default views;
- stable sort/group/subgroup and configurable fields;
- command search and direct key lookup;
- truthful pagination and export.

- [ ] **BLD-09-005** BLD-03 closes the selected ClickUp/Linear/Jira discovery
  baseline.
- [ ] **BLD-09-006** advanced query building remains usable without requiring a
  query language; expert syntax is optional future scope.

### Execution

- backlog and iteration planning;
- custom workflow and required fields;
- dependencies and blocked state;
- recurring work;
- bulk update and move;
- time/estimate/progress;
- comments, mentions, attachments, activity, and notifications;
- forms/intake and triage;
- automation with run history and failure recovery.

- [ ] **BLD-09-007** common project work is no more clicks than the measured
  competitor benchmark unless extra confirmation prevents real risk.
- [ ] **BLD-09-008** automation and bulk behavior expose partial failure and
  retry more clearly than competitor baselines.

### Planning and Management

- goals/OKRs and project contribution;
- product roadmap, program, portfolio, health, and updates;
- project updates with configurable cadence, responsible owner, reminders,
  subscriptions, last-update freshness, and an explicit stale state;
- milestones/releases and client communication;
- workload/capacity;
- risk, decision, approval, change, incident, and QA workflows;
- dashboards/reports with source drill-down;
- linked-record and roll-up fields that preserve one source record and
  authorized drill-down.

- [ ] **BLD-09-009** roll-ups reconcile to source records and never present an
  unexplained score.
- [ ] **BLD-09-010** enterprise pages stay out of the freelancer's primary
  navigation unless used.
- [ ] **BLD-09-023** project updates have cadence, owner, reminders,
  subscriptions, freshness, and a stale state; Linear/Asana reminder behavior
  is matched or deliberately exceeded, not omitted.
- [ ] **BLD-09-024** competitor migration uses BLD-05 mapping, preview, dry-run,
  idempotent commit, rollback/cancellation, and a row-error report.

### Customization and Platform

- custom fields and issue types;
- configurable statuses, cards, columns, density, and terminology;
- templates, forms, automations, webhooks, and integrations;
- API/event contract and import/export;
- responsive and accessible core workflows;
- permission and audit controls.

- [ ] **BLD-09-011** customization has limits and indexed data contracts; it
  cannot create unbounded query or UI behavior.
- [ ] **BLD-09-012** every integration follows BLD-07 ownership and does not
  create a second source of truth.

## Current Product Gap Review

- **Complete with evidence**
- **Present but incomplete**
- **Duplicate/architecturally wrong**

- route/link correctness before adding pages;
- Sprint/Cycle consolidation before expanding iteration features;
- board completeness and filter truth before adding more views;
- workflow/display separation before adding settings;
- bulk API and partial-failure contract before more bulk buttons;
- validation and tenant/project identity before richer forms;
- integration ownership before copying module records;
- visual hierarchy and overlay consolidation before decorative redesign.

- [ ] **BLD-09-013** current-state classification links to source and runnable

## StreamlineOS Differentiators

### Client Progress Studio

Freelancers, agencies, and enterprise delivery teams can publish an approved,
branded progress view from the same source records:

- current health and narrative update;
- milestones and releases;
- approved roadmap;
- completed and in-progress deliverables;
- decisions, risks, and change approvals selected for disclosure;
- files and meeting outcomes selected for disclosure;
- feedback status;
- freshness and next update date.

Every field is previewable per grant. Internal costs, notes, people data, AI
traces, audit metadata, and unapproved work remain hidden.

- [ ] **BLD-09-015** client preview and external session render the same
  projection.
- [ ] **BLD-09-016** revocation is immediate and cache safe.

### Work OS Context

Build can connect delivery to CRM customer, calendar dates, meeting decisions,
knowledge specs, documents, approved time, accounting actuals, chat/mail source
threads, and notifications without copying their records.

- [ ] **BLD-09-017** every cross-module chip or summary opens its authoritative
  source and states freshness.
- [ ] **BLD-09-018** users never need to reconcile two editable copies of the
  same customer, meeting, file, time entry, or invoice.

### Evidence-Backed Agent

The Build agent can:

- summarize scoped progress with citations;
- identify blockers, stale work, dependency risk, and missing owners;
- draft updates, release notes, plans, and triage suggestions;
- propose field, bulk, scheduling, and automation changes;
- execute only after policy-appropriate review and reauthorization;
- show cost, affected records, exact diff, evidence, and outcome.

- [ ] **BLD-09-019** agent evaluation covers hallucination, stale context,
  prompt injection, denied records, destructive proposals, and partial failure.
- [ ] **BLD-09-020** deterministic product behavior remains usable when AI is
  unavailable or credits are exhausted.

## Deliberate Non-Goals

- a second chat, mail, calendar, document, CRM, timesheet, or accounting system
  inside Build;
- separate Sprint and Cycle models for terminology preference;
- unlimited custom query language in the first release;
- every possible view on every page;
- decorative AI controls without an evidence-backed customer action;
- unbounded dashboards or custom fields;
- public client data by default;
- feature-count parity that compromises simplicity, speed, or security.
- a second Build-owned calendar record or route; Calendar is a baseline view
  fulfilled only through permission-safe sources on `/calendar`;
- arbitrary user-authored formula languages in the first release;
- multi-homed work items that copy the same ticket into many projects; a work
  item has one owning project, and cross-project visibility uses relations,
  saved views, programs, and portfolios;
- Jira sandbox scenario planning and automatic schedule commitment; agents may
  propose a reviewed schedule diff.

- [ ] **BLD-09-021** excluded competitor features have a written product reason.
- [ ] **BLD-09-022** sales/marketing claims match shipped, plan-entitled,
  evidenced behavior.
