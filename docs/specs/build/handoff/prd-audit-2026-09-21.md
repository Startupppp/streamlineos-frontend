## Verdict definitions

| Verdict | Means |
|---|---|
| SATISFIED | Met today, with a named test or gate the coordinator **ran** |
| PARTIAL | Some clauses met; the failing clause is named with a source anchor |
| NOT SATISFIED | Implementable now from static/unit evidence |
| BLOCKED | Needs a real database, browser, provider, deployed env, or human sign-off |

An item saying *every* / *all* / a matrix is SATISFIED only when a gate or
generated snapshot covers the whole set. Spot checks do not close a census.

## Findings that change the plan

**The repo had no CI at all.** `7df2c3bb2` ("Consolidate pending work
documentation and refactor QA run execution components") deleted
`.github/workflows/frontend.yml` — 891 lines, the only workflow in this repo —
and said so in none of its nine bullet points. 41 gates and 82 check scripts had
no invoker. This is the second time a commit in this program has silently deleted
load-bearing infrastructure under an unrelated title; `e192ec53b` did it to 584
files under `architecture-refactor/`. **Check `git show --stat` on any commit
whose message does not account for its file count.**

**`check:page-state-usage` was never wired, in any form.** `git log -S` over the
whole history of the workflow returns nothing, though cycles 12 and 13 both
record it as wired and report "41 gates, all invoked by a reachable run step".
It is wired now, and that claim is finally true.

**Backend CI has been red on a Build defect since cycle 2.**
`check:outbox-consumers` is blocking at `backend/.github/workflows/ci.yml:811`.
`build.incident.status_changed` is emitted twice and consumed nowhere — it is not
even in the declared registry, so the relay retries an event with no handler.
Introduced in `d46e4e348`. Deciding what should consume it is a product call, so
this is not a mechanical repair.

**A cross-project mutation hole existed inside every tenant.** `updateCycle` and
`deleteCycle` both route through `/build/:projectId/cycles/:cycleId` and neither
constrained by `projectId`. The delete also nulls `tickets.cycleId`, so it
silently detached another project's tickets; and `updateCycle`'s "one active cycle
per project" check read the URL's project while updating a cycle in a different
one, which could leave that project with two active cycles. Fixed.

**Today's sprint deletion lost capability BLD-10-012 predicted it would.**
`9662485c9` removed the `/sprints` route and all of `features/build/sprints/**`.
`features/build/cycles/` has 4 files and the API exposes only `useCycles` and
`useCreateCycle` — there is **no** frontend path to edit or complete a cycle, no
planning board, no ticket mover, although the backend has `PATCH`/`DELETE
:cycleId`. `cycles-page.tsx` renders a "Completed" section nothing in the UI can
populate. Velocity is fine — Reports owns it, per D09.

**`check:contract-vendor` now passes, so contract results mean something.** The
two `openapi.json` files are byte-identical. The handoff's "stale vendored
contract" caveat is out of date, and `check:contract-parity`'s Build finding —
`assignees` in `build-tickets-core-schema.ts:101` — is now measured against the
real backend contract. Note `07-architecture-integrations-prd.md:39-40` claims
the backend omits `assignees`; it does not (`build-tickets-response.schemas.ts:141`).

**Three red checks are one stale `.next` build.** `check:route-bundle-budget`,
`check:web-vitals-budget` and the single frontend typecheck error all trace to a
`BUILD_ID` mismatch. One `next build` clears all three. Both budget gates refuse
to publish rather than reporting a false verdict — that is correct gate design.

**`check:type-assertions --update-ledger` cannot help.** It advertises "can only
lower" and **refuses outright** while any file would go up; 24 would, so it wrote
nothing. The 20 stale entries stay until those 24 assertions are removed.

## Two items reopened

**BLD-05-004 and BLD-05-037 were both ticked on a scan that cannot see a
multiline declaration.** `features/build/cycles/cycles-page.tsx:59-104` is a
45-line inline Zod object in a page component, supplying `zodResolver` at `:149`,
with no `features/build/cycles/*-schema.ts` anywhere. Measured both ways today:

```
rg -l   "z\.object\("          features/build … --glob '!*-schema.ts'  → 0 files
rg -U -l "z\s*\n\s*\.object\(" features/build … --glob '!*-schema.ts'  → 1 file
```

BLD-05-037's closure had already widened the **constructor set** past `z.object`
to `discriminatedUnion`/`tuple`/`record` — a real gap, correctly found — but kept
the **line-shape** assumption that caused the original miss. The same defect sits
in `features/settings/__tests__/settings-schema-placement.contract.test.ts:40`,
which is the third instance of it. **A schema-placement detector in this repo must
tolerate a line break between `z` and its method**; until one does, neither item
can close.

Both are reopened with the measurement recorded inline, and the superseded closure
text is retained for provenance rather than deleted.
