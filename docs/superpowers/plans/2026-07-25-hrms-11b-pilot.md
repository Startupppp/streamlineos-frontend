# HRMS Plan 11b — Migration Pilot (money→cents · JSONB→child-table)

> Two pilots demonstrating the target pattern on **one table each**, so you can review the shape + backfill before I roll it across the remaining ~16 money tables and ~20 JSONB arrays. Each follows §19's safe sequence: **add (additive, non-breaking) → backfill → cutover → drop**. This commit ships **phases 1–2 (add + backfill SQL)** only — the cutover changes read/write paths and (for money) needs runtime correctness testing, so it's the reviewed follow-up.

## What shipped in this commit (additive, non-breaking)
- **Money pilot:** `bonuses.amount_cents` — a `bigint` column (nullable). The existing `amount` `decimal(15,2)` is untouched and still the source of truth, so nothing breaks.
- **JSONB pilot:** `one_on_one_action_items` — a normalized child table for `one_on_one_meetings.action_items` (each item its own row: individually completable, reorderable, indexable, soft-deletable). The `action_items` JSONB column is untouched and still the source of truth.

Both are pure schema additions — backend `tsc` + `eslint` green, no service reads/writes them yet.

## Step 1 — generate the migration
```bash
pnpm -C backend db:generate
```
This emits `ALTER TABLE bonuses ADD COLUMN amount_cents bigint;` and `CREATE TABLE one_on_one_action_items (...)` (+ its indexes). Review the SQL.

## Step 2 — add the backfill to the generated migration
Append these to the generated migration file (they're idempotent):

```sql
-- Money: rupees(decimal) -> paise/cents(bigint)
UPDATE bonuses
SET    amount_cents = ROUND(amount::numeric * 100)
WHERE  amount_cents IS NULL;

-- JSONB action_items -> normalized rows (preserves order via WITH ORDINALITY)
INSERT INTO one_on_one_action_items (meeting_id, org_id, "text", done, sort_order, created_at)
SELECT m.id, m.org_id, (item->>'text'), COALESCE((item->>'done')::boolean, false), (ord - 1), m.created_at
FROM   one_on_one_meetings m
CROSS JOIN LATERAL jsonb_array_elements(m.action_items) WITH ORDINALITY AS t(item, ord)
WHERE  m.action_items IS NOT NULL AND jsonb_typeof(m.action_items) = 'array';
```
Apply with `db:migrate`. After this, both new structures are populated and verifiable, while the old columns still drive the app.

## Step 3 — cutover (the reviewed follow-up; needs a runnable app)
Once you've reviewed the shape and can run the stack:

**Money (`bonuses.service.ts`):**
- `createBonus`: accept rupees input → store `amountCents = Math.round(rupees * 100)` as source of truth (stop writing `amount`).
- reads: expose `amount` in the API by converting `amountCents / 100` (frontend contract unchanged).
- After a bake period + verifying every payslip/FnF/report total matches to the paise, drop the `amount` decimal column.
- **Why runtime-gated:** money math must be verified end-to-end (create → payslip → FnF → report) before the old column is removed.

**JSONB (`performance-reviews.service.ts`):**
- `createOneOnOne`/`updateOneOnOne`: write/replace `one_on_one_action_items` rows in the same transaction (instead of the JSONB array).
- `listOneOnOnes`/detail reads: load the child rows and map back to `actionItems: {text, done}[]` at the boundary (frontend contract unchanged), or expose row ids for per-item toggles.
- After verifying, drop the `action_items` JSONB column.
