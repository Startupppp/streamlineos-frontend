# Reason framing — gap → sellable reason
**Lane:** PM · **Updated:** 2026-10-01 (IST)  
**Audience:** Positioning, sales-assist copy, Completeness prioritisation  
**Rule:** A row is a *gap to close* until Build ships it; only then is it a *sellable reason*.

---

## 1. Anatomy of a PM-owned reason

| Column | Meaning |
| --- | --- |
| **#** | Stable PM reason ID (aligns to CI seed where shared) |
| **ICP tags** | `F` Freelancer · `PM` Product Manager · `PjM` Project Manager (one or more) |
| **Theme** | Activation · Client wedge · Delivery · Insights · Collab roles · Hierarchy · Extensibility · Finance · Auth · Ops niche · Trust craft |

| **Today status** | `BEHIND` · `BEHIND craft` · `PARITY` · `PARITY-seeking` · `SHIPPED` · `UNIQUE-potential` · `Not Now` |

---

## 2. Transformation recipe

```
CI / Completeness gap
  → name the buyer job blocked
  → tag ICP(s)
  → write benefit when shipped (en-GB)
  → name Direct to match/beat (from CI cut or walk)
  → keep status BEHIND until QA VERIFIED ship
  → only then promote to sellable claim in marketing
```

**Bad (premature):** “Build has Linear-class cycles.”  
**Good (gap):** “When Active cycle chrome ships, PMs see current cycle on overview + board — match Linear Cycles discoverability.”  
**Good (shipped):** “Active cycle on overview and board so the team always knows what ‘now’ means.”

## 3. ICP tag rules

- Tag **every** row with ≥1 of F / PM / PjM.
- Prefer **two tags** when the job is shared (e.g. invite accept = F+PM+PjM).
- Do not tag Ops niche rows as primary F reasons unless the freelancer explicitly runs QA/ITSM — keep niche honest.
