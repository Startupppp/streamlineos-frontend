# Customer value and differentiation

Status: Planned roadmap; historically observed features are Current unverified

## Problem Statement

A list of 100 useful features can mix competitive necessities with unique value. Buyers need verified workflow outcomes, and engineering needs priority and evidence rather than a feature-count claim.

## Solution

Keep the original 100 IDs, classify each as Baseline requirement, Workflow advantage, or Differentiation hypothesis. Baseline means needed to compete, not unique. Advantage means connected workflow value, not exclusive availability. Hypothesis requires customer and comparative validation before superiority claims.

## User Stories

1. As a freelancer, I want approved delivery connected to time and invoice context, so that work does not disappear before payment.
2. As a PM, I want evidence and scoring linked to delivery outcomes, so that priorities can be reviewed later.
3. As a PjM, I want milestones, dependencies and change control linked, so that commitments stay explainable.
4. As a buyer, I want claims tied to tested outcomes, so that I can choose responsibly.

## Implementation Decisions

Priority P0: invite acceptance → module assignment → atomic client grant. P1: reliable discovery, contribution, work/filters/client feedback. P2: governance, discovery/outcomes and commercial projections. P3: deeper scenarios/retainers/enterprise deployment. These priorities order delivery, not customer importance.

## Testing Decisions

Each reason requires evidence for the stated customer journey, not only source presence. Comparative claims name competitor, plan, configuration, date and evaluated workflow. Evidence that peers offer portals, dashboards, AI, time, forms, and views rules out generic uniqueness claims. A superiority statement needs comparative results and customer validation.

## Out of Scope

Cheaper/prettier/all-in-one claims, guaranteed market leadership, and treating these reasons as currently shipped.
