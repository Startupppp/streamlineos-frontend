## 3. Sequencing Constraints

**MUST land before** → **reason**

1. **A1 before A2, C1, C2, C3, C6** — `ENCRYPTION_KEY` must be required + set in prod before any encrypt-or-throw code ships; otherwise the deploy order could leave a window of throwing errors.
2. **A2 before B3, C1, C2** — `encrypt()` must throw (not silently return plaintext) before it is called from the new encrypted write paths.
3. **B1, B2, B3 before C1, C2** — Canonical crypto helper must be consolidated before the new encryption calls import from it.
4. **C1+C2+C3 must deploy atomically** — Writing encrypted rows before dual-mode read is live means users see ciphertext. Dual-mode read going live before encrypted writes is safe (no-op — it handles plaintext the same way).
5. **C1-C3 before C6** — Backfill must only run after the write path encrypts and the read path decrypts; otherwise backfill re-encrypts rows that are then double-encrypted.
6. **C1-C3 verified in prod before C6 runs** — Operator confirmation required (see §6).
7. **A3+A4 must deploy atomically** — A3 denies null-owner files; A4 registers e-sign/payslip tables. Deploying A3 alone will break e-sign/payslip downloads.
8. **E1 (operator org_modules backfill) before E2 (ModuleGuard activation)** — Absolutely non-negotiable. Even a single missing org_modules row causes complete HR 403 for that org.
9. **G1 before G2** — G1 fixes the buggy query inside the method that G2 wraps in a transaction; both must be correct simultaneously.
10. **K1 before G1 is verified** — The leave balance unique index change (K1) and the missing-orgId fix (G1) together close the multi-org leave isolation gap.
11. **I1 before I2** — Frontend catalog keys must exist before role templates are extended; otherwise `useCan()` calls still return false even after the template grants the key.
